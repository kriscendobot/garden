### Design PR #995 (`@endo/claude`)

A new design opened as draft PR #995 (`designs/endo-claude.md`): an Endo package
giving a guest LLM inference from a Claude subscription through a hermetically
sandboxed `claude -p` whose only capability surface is one guest formula's granted
facet, projected as MCP tools (`jobs/tada/design-endo-claude.md`). A follow-on
revision folded four peer-correction points, grounding the MCP bridge on the merged
`endo-gateway-mcp` and the stdio shim, naming `daemon-agent-tools` as the hard
dependency for capability-scoped tools, and recommending a local stdio shim as the
concrete v1 (`jobs/tada/design-endo-claude-mcp-groundwork.md`). The design then
entered its own gauntlet (clean, panels 1 and 2, fixes 1 and 2). The panel's
practice of running the design's runnable premises rather than trusting its
"verified against the CLI documentation" claim proved decisive: the critic,
skeptic, and breaker seats independently found that the mandatory `--bare` flag
reads neither `CLAUDE_CODE_OAUTH_TOKEN` nor the keychain, so it cancels the
subscription-token value the whole package rests on; that `--strict-mcp-config`
takes no argument, so the literal argv would silently start with zero MCP servers;
that no deny-by-default permission mode exists; and that rendering untrusted facet
method names into a comma-joined allow-list is an argv-injection surface
(`entries/2026/08/16/060905Z-result-gardener-a3e8c0.md`,
`entries/2026/08/16/061004Z-result-gardener-6ff5b9.md`,
`entries/2026/08/16/064524Z-result-gardener-a29104.md`). The critic routed a
structural lesson to the liaison: a design panel should run a design's premises when
they are cheap to run (`entries/2026/08/16/060921Z-message-gardener-081392.md`).
