### The #475 byteArray-narrowing arc

Work on `feat/narrow-bytearray-to-uint8` (narrowing `byteArray` to a plain frozen
`Uint8Array`) drove the most activity, almost all in response to a running review
conversation with erights across roughly a dozen jobs. The recurring question was
what the `.buffer.immutable` accessor actually distinguishes; the settled answer,
corrected in both PR replies and a misleading `byteArray.js` code comment, is that
it separates immutable-backed from mutable buffers, not emulated from genuine
views. Over the day the design converged on `ArrayBuffer.isView` as the single
committed fidelity loss: `byteArray.js`'s brand check was recast to an
`isView`-gated exact test, `@endo/bytes` `compare.js` was rewritten to index
genuine views in place and copy only emulated wrappers, and the prose and
changesets were rewritten so the integer-indexed-read and `[Symbol.toStringTag]`
losses became incidental consequences rather than committed guarantees. The head
advanced through `b4a8175`, `9d397b5a65`, `9b202d4554`, and finally `2d1200239f`,
the last of which closed a failing pass-style test that an earlier racing job had
deferred to CI.

Two real CI reds (a Prettier line-width miss and a `TS2345` on a narrowed index
read) were fixed and the remaining reds confirmed pre-existing flakes. Review
directives also spawned spec and regression work: several jobs specified the
non-replacement of the typed-array getter as a deliberate fidelity loss and
duplicated the guard test into `@endo/immutable-arraybuffer`. A silent-merge-drop
audit found three latent bugs where the narrowing was not carried onto consumers

`fix-gauntlet-shorthand-citation` closed a silent gauntlet-bypass path: the two

which the full-URL-only regexes in the stager and gate both missed, so no gauntlet

shorthand.

`garden-root-repo-guard-gc-lock-contention` fixed the root-repo guard conflating a
`git gc` lock collision with a damaged object store: it had been escalating to a
roughly 173MB `fetch --refetch` and paging the maintainer with a hand-repair
recipe that had no missing object to act on (the observed alert was self-refuting,
reporting zero missing objects). The classifier now distinguishes lock contention
(backs off quietly, no refetch, no alert), zero-missing gc failures (also quiet
backoff), and genuine non-zero missing counts (the unchanged escalation path). The
contention source was understood as git's own auto-gc racing on the shared root
object store. A larger follow-up of setting `gc.auto=0` was noted but deferred.

`self-improve-job-basename-isodate` responded to a hand-posted orchestration child
silently colliding with an already-completed job of the same base. It documented a
canonical basename-shape convention in the job-board skill (bare base for stable
one-shot asks, an ISO-date or identity suffix for recurring verbs against the same
target) and cross-linked it. An audit of the deterministic minters found each
already carries a disambiguator and needs no change; the real gap was hand-posted
recurring jobs, which the convention now governs. It also made `post-job.sh` and
`post-plan.sh` emit a loud WARN when a post collides with a completed job rather
than a silent no-op.

### Designs written

`garden-design-follower-self-deploy` (designer, draft PR `kriskowal/garden#73`)
designed a follower self-deploy trigger so an unattended non-leader host advances
its own deployed version on the local upgrade signal without a human. The design
(`designs/follower-self-deploy.md`) covers a leader-gated no-LLM daemon reading
only the local `upgrade-ready` file with a per-sha settle window, keeps the leader
session-orchestrated as the canary, proposes a lossless dirty-tree self-heal, and
draws a hard attestation boundary (self-deploy triggers on host-local signal plus
git ancestry, never a bus message, so it is not a back door around the attested
sysop `deploy` op). Implementation was deliberately deferred to a follow-on build.

`garden-gauntlet-panel-fix-nonconvergence` investigated why the gauntlet panel and
fix loop repeatedly fails to converge, reading 13 stage records across four
gauntlets. Verdict: the panel keeps moving the target rather than approaching a
fixed point, so raising `max_iterations` cannot help. Three mechanical causes were
identified: single-blocker disposition with no severity floor (a copyeditor's
em-dash blocks as hard as a critic's RCE finding), no cross-round memory (each
round is a stateless re-review, and rewrites create fresh critique surface), and
stale-base panel-kind flips (the diff is sensed against a stale `origin/llm`, so
small design PRs get reviewed as large code panels). Halts were found mostly

### Self-heal watcher sweep

About sixteen self-heal jobs hardened the standing per-repo watchers against two
crash-loop classes, most resolving through a single shared-handler fix rather than
per-repo code.

The larger family (roughly a dozen `comment-watcher` jobs across agoric-sdk,
agoric-3-proposals, cosgov, endo, endo-but-for-bots, list, moddable, ocapn,
proposal-compartments, test262, vattr97, ymax-stdio-mcp) addressed a crash-loop on
repos with GitHub Issues disabled: a repo-level `issues/comments` 404 was being
treated as a fetch failure. The fix in `comment-source-gh.sh` authoritatively
detects `has_issues=false` through a cached repo read on the already-404'd path,
classifies the surface as structurally absent (logged once per tick at INFO, no
maintainer alert), and recovers per-PR comment coverage by walking each open PR's
`issues/<n>/comments` (which still serves with Issues off). A 404 while Issues are
enabled still freezes the cursor, so genuine gaps are not swallowed. Because the
fix lives in the shared handler and is idempotent, siblings claimed by peers
resolved without further code change. The remaining step (deploying `main2` to the
root and clearing any failed units) is gated on the deliberate deploy and left to
the liaison.

The smaller family (`ci-watcher` jobs for minion-town and test262) added the Go
JSON-decoder wording `unexpected end of JSON input` to the shared
transient-GitHub-API signature set in `common.sh`, so a truncated or dropped
response body is retried and WARN-skipped instead of crashing `garden-ci-watcher`.
This one-line signature addition repairs every consumer of the shared classifier;
a companion job added the end-to-end ci-watcher regression test proving the
source-failure path degrades to WARN and exit 0 rather than reaching the FATAL die.
