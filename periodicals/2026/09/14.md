## Iron Horse (XS port)

The `ironhorse-port-xs-frame-locals-limit` job ported XS's exact 65535-slot
per-frame ceiling to Iron Horse and opened draft PR #1278 (head `b09834bac8`). The
ceiling is a memory-safety bound, not mere conformance: frame-slot operands encode
as `u16`, and past 65535 the opcode width selector bumps to a `_4` variant that
does not exist, so the scoper now rejects any frame whose `scopeMaximum` exceeds
65535 with a catchable syntax error before the coder can emit corrupt bytecode.
One `record_scope_count` helper folds in all four accumulation paths, and the
change ships boundary and per-path regression tests that compile and run under
`cargo test`, with `format-ironhorse` and `test-ironhorse-calibration` green on the
head. The report notes the ceiling is normally shielded by a lower 65534-symbol
cap and parser stack depth, so the guard is defense-in-depth
([port report](../../../jobs/tada/ironhorse-port-xs-frame-locals-limit.md)). The
weekly `xs-frame-locals-limit-upstream-watch` schedule also fired a clean
`xs-locals-limit-check`, which will reconcile the port once the upstream XS fix
lands.
