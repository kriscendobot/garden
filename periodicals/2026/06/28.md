## Multibot leader/follower topology (the structural headline)

The day's spine was issue kriskowal/garden#11, Multibot — preparing the garden to
run across several bot hosts without singleton services double-firing.

- **Landed (`service-host-roles-singletons-on-main-host`, commit `edc78369b`).**
  Gardeners run on every host; the leader-only singletons (scheduler, foreman,
  bulletin, watchman broadcast, the comment/mention/issue-inbox watchers, the
  liaison inbox Monitor) gate on a journal marker via an `is-main-host.sh`
  `ExecCondition` (exit 0 = leader). Introduced the `GARDEN` host-identity knob so
  an operator can spawn a parallel pool from a worktree, plus a TTL-cached,
  fail-open predicate so a journal outage never wedges single-host behavior.
- **Simplified the same day (`leader-marker-…`, commit `5bafb2ef7`).** Per a
  kriskowal directive, the marker moved from `hosts/main-host` to a single
  `journal/leader` file holding the leader's `GARDEN` identity, and the internal
  `GARDEN_HOST` alias was removed everywhere in favor of one `GARDEN` var (61
  files: predicate now leader iff `leader == $GARDEN`, the `GARDEN_MAIN_HOST_*`
  env family renamed to `GARDEN_LEADER*`). Script filenames were deliberately kept
  to avoid churning 13 ExecConditions.
- **Future-proofed (`design-raft-leader-election`, PR kriskowal/garden#14).** A
  design-only PR (+455/-0) adapting `kriskowal/cask`'s election-only RAFT to the
  journal2 CAS as transport, proposing a half-hour-cadence lease-based election to
  replace the manual, no-failover marker. Honestly scoped: today's two-host fleet
  is quorum 2/2, so no single-fault failover until a third voter is admitted.

This host (endolinbot2) remains the **follower**; the leader is endolinbot.

## The GitHub Pages bulletin (built, steered, re-architected, finished)

renders the live `journal2:README.md` and lets a maintainer post a thread back to

  client-side app under `docs/bulletin/` reading the Contents API and writing one
  atomic reply commit via the Git Data API (fine-grained PAT, with an optional
  device-flow path behind a CORS shim).
- **Steered mid-flight.** Seconds after that push, the maintainer ruled out
  committing rendered content to `main2` and asked for a CI workflow on `main2`
  triggered by `journal2` changes. The directive and the builder's "pushed to
  main2" report crossed 25 seconds apart; the deadmail handler reconstructed the
  collision, posted `bulletin-rearch-ci-from-journal2`, and replied on the issue
  surfacing the real GitHub constraint (a `main2` workflow can't fire on a
  `journal2` push without YAML on the orphan branch, so the working path is
  `repository_dispatch` + `workflow_dispatch` + a scheduled safety net).
- **Re-architected, then reverted.** The CI-rendered version was built and
  validated end-to-end, pushed as `33193fed4`, then reverted — a later maintainer
  steer superseded it, so net `main2` was returned to the blessed state.
