# Daily progress summary: 2026-07-08 (Pacific)

## Abstract

A quiet, recovery-shaped day whose two threads were a finished design track and a
broken host. On endojs/endo-but-for-bots the daemon storage-platform work closed
out: the Cloudflare storage design landed as draft PR #638 with a runnable toy
scaffold, its sibling AWS-storage design (PR #637) took a coordination fix to its
`designs/README.md` totals that arrived as a dead-lettered message and was promoted
to its own job, and both PRs were then shepherded to fully green CI after
prettier-only lint reds (plus one macOS test flake on #637 that cleared on re-run).
Underneath all of this, one of the two hosts, `endolin-garden2`, was down for the
whole window: its foreman pump and its gardener handlers kept failing with exit
code 1 and "designer: command not found" / "builder: command not found", starving
that host's board pump and firing a steady stream of watchdog alerts into the
maintainer inbox. The other host, `endolin-garden`, reaped every stalled claim and
completed all of the affected jobs, so no work was lost, but the `garden2`
breakage is an open item for the maintainer. Early in the window the fleet also
wrote and pushed its own prior-day summary, the periodical for 07-07.

## endo-but-for-bots (endojs/endo-but-for-bots)

The fork was the only project with substantive work in the window, and all of it
converged on one pair of sibling designs: a storage platform for the Endo daemon,
one targeting Cloudflare and one targeting AWS.

### Daemon storage-platform designs (PRs #637, #638)

The Cloudflare storage design job completed and opened draft PR #638 on the bot
fork, branch `design/endo-daemon-cloudflare-storage`
(`../../../jobs/tada/design-endo-daemon-cloudflare-storage.md`). After a mid-flight
maintainer redirect from `kriscendobot/endo` to `endojs/endo-but-for-bots` at
`llm`, the designer studied the fork's real storage seams, corrected an upstream
misconception in the design doc (upstream endo's node platform is filesystem plus
crypto with no sqlite), and mapped primitives onto Cloudflare services with stated
justifications: Durable Object SQLite chosen because its synchronous API is the
only Cloudflare SQL surface that can honestly back the daemon's synchronous
prepared-statement seam, D1 evaluated and rejected as async-only for that seam, R2
for the content store, and KV rejected for authoritative state. The delivery
included a third `Database` engine (`better-sqlite3-do.js`) that leaves
`daemon-database.js`, `pet-store.js`, and the persistence powers unchanged, an R2
`FilePowers` implementation with atomic rename-by-copy commit, and six green tests
against in-memory mock bindings.

A second, smaller piece of the same track arrived indirectly. The Cloudflare
designer's final coordination note to the already-finished AWS-storage designer was
dead-lettered and promoted to its own job
(`../../../jobs/tada/deadmail-20260708T074539Z-84584c.md`). Carrying it forward
turned up a real defect rather than a courtesy note: the AWS design PR #637 had
added its row to the summary table and the milestone buckets but left the top-level
totals prose at the base 143 designs / 28 Proposed, despite claiming the totals
were synced, while the Cloudflare branch had correctly bumped its own to 144 / 29.
The job fixed the AWS branch's totals prose to 144 / 29 with a dated recount note,
pushed it to `design/endo-daemon-aws-storage`, and posted a merge-coordination
comment on PR #637 so whoever merges the two second reconciles to 145 / 30.

### CI shepherding of both design PRs

Both design PRs were auto-shepherded to green after red CI, and both reds were the
same shape: a prettier formatting complaint on newly added test files, nothing
behavioral. PR #638's two `lint` jobs were the only reds, cleared by running
prettier on `packages/daemon/test/cloudflare-powers.test.js`, after which all 24
checks passed (`../../../jobs/tada/endojs-endo-but-for-bots-pr638-shepherd.md`). PR
#637 was noisier: two `lint` failures from prettier on the AWS test files plus one
`test (24.x, macos-15)` leg that turned out to be a flake; the prettier fix landed
on the head branch and the flaky leg passed on re-run, taking the rollup to 24 of
24 (`../../../jobs/tada/endojs-endo-but-for-bots-pr637-shepherd.md`). Both PRs stayed
draft, and neither shepherd posted a green-run comment because the auto-dispatched
jobs carried no per-action authorization to comment on the external repo.

Both shepherds and the design job did their work on the healthy `endolin-garden`
host. PR #637's shepherd job in particular had to be rescued there: it was claimed
and failed three times on `endolin-garden2` (the handler exiting rc=1) before that
host's stale claims were reaped and `endolin-garden` completed it.

## garden-meta

The untagged stream this window was almost entirely fleet health, and it tells one
story: a two-host fleet in which one host was broken and the other carried the load.

### The garden2 host outage

Throughout the window the `endolin-garden2` host was failing at two layers. Its
foreman pump handler failed repeatedly with exit code 1, and the watchdog alerts it
sent to the maintainer inbox name the cause plainly: `designer: command not found`
and `builder: command not found` from inside `foreman-claude.sh`, which starves
that host's board pump
(`../../../inbox/maintainer/unread/20260708T140409Z-ec6db4.md`). At the gardener
layer, individual job handlers on the same host failed rc=1 and were escalated to
the gardener inbox and left in `doin` for the reaper, recorded as a run of error
entries (`../../../entries/2026/07/08/070558Z-error-gardener-e9adcf.md`,
`../../../entries/2026/07/08/075335Z-error-gardener-81c48a.md`,
`../../../entries/2026/07/08/090340Z-error-gardener-7ba638.md`,
`../../../entries/2026/07/08/101320Z-error-gardener-0e4ad3.md`). The watchdog and
inbox messages from this host arrived on a roughly hourly cadence across the whole
window and remain unread in the maintainer inbox. This is the one item worth a
maintainer's attention: `garden2` needs its handler PATH or environment repaired,
because as configured it cannot run any Claude-backed job.

### Reaper and cross-host resilience

The failure did not cost any work, because the reap-and-reclaim path did exactly
its job. Each time a `garden2` gardener failed and left a claim stale, the reaper
requeued it and a `garden` gardener re-claimed and finished it. That path recovered
the daily-progress-summary job for 07-07 (first claimed and failed on `garden2`,
then completed on `garden`), the two shepherd jobs above, and the design work. The
board pump on the healthy host, the reaper, and the deadmail promotion machinery
all stayed live and correct while the sibling host was down.
