# Topic: local-first-sync

> Abstract: Local-first data ownership and efficient replica synchronization over an immutable, content-addressed, append-only store: work offline against a local instance, hydrate missing content on demand, and reconcile divergent replicas deterministically. Seeded 2026-07-06 from `dialog-db/dialog-db` (Irakli Gozalishvili's embeddable local-first database): the six design goals, the causal (B-theory) temporal model that replaces a global wall-clock timeline with per-fact causal chains, the Merkle-CRDT query-time merge that reconciles concurrent changes Git-style, the deterministic content-addressed Probabilistic B-Tree + segment layer whose byte-identical layout makes diff-based sync cheap, the blob-store + DID:key-mutable-pointer decoupling that enables multi-remote push/pull with compare-and-swap, and the user-chosen privacy-efficiency tradeoff. Lineage: Ink & Switch local-first, Merkle-CRDTs, RhizomeDB causal consistency, Prolly Trees. Distinct from `datalog-query` (the read/model side), `content-addressed-storage` (the cask-specific CAS corpus this shares the Merkle-tree idea with), and `change-propagation` (the reactivity theory).
