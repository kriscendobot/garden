Abstract: Serverless **multi-tenant platform** hosting — running many end-customers' code (untrusted, or AI-generated) on shared infrastructure with per-tenant isolation, a programmable dispatch/router layer, per-tenant resource limits, egress control, and fleet organization by tenant. The exemplar is Cloudflare **Workers for Platforms**: a dispatch namespace holds all customers' user Workers; a dynamic dispatch Worker is the platform's request entry point that routes each request to the right user Worker and enforces platform policy; user Workers are the deployed customer code; an optional outbound Worker intercepts customer egress; custom limits cap each tenant's CPU time and subrequests; tags organize and bulk-manage the tenant fleet; and untrusted-versus-trusted isolation modes set the cross-tenant security boundary. This topic is deliberately vendor-agnostic in name (the pattern generalizes to any "platform on a serverless runtime"); the current corpus is the Cloudflare Workers-for-Platforms documentation set.
