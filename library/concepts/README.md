# Concepts

Per-concept lookup pages. An agent reaching the library with a *specific term* in mind (a code symbol, a domain phrase, a proper name) arrives here via [`keywords.md`](../keywords.md): a keyword resolves to a concept-id, and this directory holds one short page per concept.

Each page contains:

- A one-paragraph definition of the concept.
- A `Sections that touch this concept` table with the relevant section files and one-line summaries of what each one contributes.
- A `See also` list of adjacent concept-ids.

This index is a third axis next to [`sources/`](../sources/README.md) (by provenance) and [`topics/`](../topics/README.md) (by broad subject taxonomy). Use it when:

- You know the **exact term** but not which source or topic owns it.
- You want **all the angles** on one concept (a concept page is allowed to point at multiple sources and at sibling concepts, including ones that *abandon* the concept — see [[crdt-in-formula-persistence]] for the canonical worked example).
- You need to **disambiguate** — concept pages collect "this is not that" notes so the next reader's search succeeds where yours did.

### Distributed-ocap cluster (added 2026-06-27 by `ingest-ocap-library-sections`)

Six interlocking distributed object-capability concepts, synthesized over already-ingested OCapN spec, Miller-paper, and `@endo` sources. Three pre-existed ([[granovetter-operator]], [[pass-invariant-handle-equality]], [[promise-pipelining]]) and gained cross-links; five are new here:

- [three-party-handoff](three-party-handoff.md) — the CapTP protocol that realizes the Granovetter operator *across separate sessions*: Gifter / Receiver / Exporter roles, the deposited gift + signed `desc:handoff-give` / `desc:handoff-receive` certificates, secure against a man-in-the-middle (OCapN CapTP draft § Third Party Handoffs).
- [sturdyref](sturdyref.md) — a persistent, offline capability reference: a Peer Locator + unguessable `swiss-num` from which a live CapTP reference is re-obtained after partition or restart; the *Initial Conditions* mechanism made durable (OCapN Locators draft + Concurrency Among Strangers §9.2).
- [distributed-confinement](distributed-confinement.md) — Lampson's confinement problem solved across vats: Max's code + Cassie's state, controlled vs uncontrolled subjects, non-discretionary capabilities, the data diode; the *Confinement Myth* is false in Model 4 (Paradigm Regained §5 + Capability Myths Demolished).
- [eventual-send](eventual-send.md) — `E(target).method(args)` / `E.when`: message an object eventually, local-or-remote-or-promise uniformly, backed by `HandledPromise`; the umbrella over [[promise-pipelining]] and [[handler-protocol]] (`@endo/eventual-send` + Concurrency Among Strangers).
- [grant-matcher-puzzle](grant-matcher-puzzle.md) — Mark Miller's erights.org equality puzzle (two mutually-distrustful donors, Alice and Dana, matched to a common charity KEQD by a trusted Grant Matcher) that motivates pass-invariant equality and reliable handoff transport against a capability man-in-the-middle (the transparent-forwarder "Alice Gets Greedy" attack). **Source ingested 2026-06-27** as [`web--miller-grant-matcher-puzzle`](../sources/web--miller-grant-matcher-puzzle.md) (6 sections, from the Internet Archive capture — erights.org / caplet.com were down); concept promoted `draft` → `current`.

- [tripartite-identity](tripartite-identity.md) — Randy Farmer's **identity-decomposition pattern** (Habitat Chronicles, 2008): split a user's identity into three separable identifiers — the **account identifier** (permanent, unique, random, inert DB key with no inherent public capabilities — POLA applied to identity), the **login identifier(s)** (session auth via name/password or federated **capability-based logins** from OpenID / OAuth / Facebook Connect), and the **public identifier(s)** (the non-unique, compound, mutable, context-plural social face). The IIW key insight: an RP should see only the Public ID plus a **permission-bound session key**, never a publicly-shared identifier used for authentication.
