# subjective-aggregation

The architectural claim that in a distributed capability system, **each participant may *subjectively* aggregate arbitrary sets of objects into composites for the purpose of reasoning about trust** — and *different* participants will employ *different* aggregations according to their own ignorance, suspicions, or lack of interest in finer distinctions. The framing is canonical to *Capability-Based Financial Instruments* (Miller-Morningstar-Frantz 2000) §4.3, with the most-quoted aphorism: **"only trust makes distinctions."** A fully paranoid actor models the entire world as a monolithic conspiracy against them; only with some trust can finer distinctions be drawn between separately-trustable parts of the world. The structural payoff for distributed-system design is the *economy of suspicion*: **mistrust of a vat is equivalent to ignorance of the internal relationships among the objects hosted by that vat**. A malicious vat hosting one set of objects can only cause external effects equivalent to a correct vat hosting some different (maliciously coded) set of objects — so capability analysis can, without loss of generality, **reason as if it is only suspicious of objects**, regardless of whether vats themselves are trusted.

The concept underwrites Endo's per-bundle trust posture and the broader vat-as-TCB framing of capability theory: to objects within a vat, their hosting vat is their Trusted Computing Base — their own operation is at the mercy of the TCB with no escape. *Bob's behavior can be seen as an aspect of VatB's behavior*. Only if Alice trusts VatB to behave properly — that is, *as if it is actually hosting separate objects interacting with each other by capability rules* — does it make sense for Alice to even reason about Bob as being in any way separately trusted from Joe, another object in the same vat. The subjective-aggregation framing is what gives distributed capability analysis tractable scope: each party reasons strict-over-its-own-behavior, conservative-over-everything-else (subjective-aggregation lets each party choose *what counts as "everything else"*).

## Common confusions

- **"Subjective aggregation means different parties see different graphs."** No — same graph, different aggregations. All parties see the same reference graph; what differs is how each party *groups* objects in the graph into composites for trust analysis. The structural distinction is between the *objective* (graph topology) and the *subjective* (how to coarsen the topology for one's own reasoning).
- **"Subjective aggregation requires central coordination."** §4.3 is explicit about the opposite: each party chooses its own aggregation independently; the system as a whole satisfies *both* parties' policies *without* either party knowing how the other chose to aggregate. *Mutually-suspicious composition* is the operational discipline.
- **"Subjective aggregation eliminates trust."** No — it makes trust a *first-class variable*. A fully paranoid actor aggregates the world into a single monolithic conspiracy; trust is the gradient that allows finer distinctions. The §4.3 closing aphorism — *only trust makes distinctions* — is the architectural framing: refusing to make a distinction is equivalent to suspicion; finer distinctions require trust to draw them.
- **"Mistrust = ignorance is a tautology."** It is structurally non-trivial. §4.3's argument: "a malicious vat hosting one set of objects can only cause external effects equivalent to a correct vat hosting some different (maliciously coded) set of objects." So the *external observable behavior* of a malicious vat is indistinguishable from a hypothetical correct vat hosting different objects — which means, for analytic purposes, *we don't need to distinguish a malicious vat from a vat full of malicious objects*. We can reason as if only suspicious of objects. This is the economy of suspicion the §4.3 framing argues for.
- **"This is just relativism."** It is not. Subjective aggregation works *because of* the objective structure of the access graph: the four-ways-to-acquire-references constraint means *only connectivity begets connectivity*, so subjective aggregations respect the same underlying graph. The *subjectivity* is in how the same graph is coarsened for analysis; the *objectivity* is in the graph itself.
- **"Subjective aggregation makes formal verification impossible."** No — it makes *the right kind* of formal verification possible. Each party can verify the properties it cares about over its own choice of aggregation; the composition of those verifications gives system-wide guarantees. The 2003 Paradigm Regained §5.4 mutually-suspicious composition framing is the formal substrate.
