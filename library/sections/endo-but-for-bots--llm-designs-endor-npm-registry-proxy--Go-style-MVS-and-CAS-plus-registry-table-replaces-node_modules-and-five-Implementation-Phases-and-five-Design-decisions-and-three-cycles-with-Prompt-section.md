## §The-load-bearing-substitution: CAS + Registry Table replaces `node_modules`

> Today, running a JavaScript program with npm dependencies requires:
> 1. A `package.json` declaring dependencies.
> 2. Running `npm install` to populate `node_modules`.
> 3. A Node.js runtime (or a tool that understands `node_modules` layout) to resolve `import` specifiers.

§Three-prerequisites-to-running-npm-code-today + §the-design-eliminates-all-three.

§Replacement: §packages-stored-in-CAS-content-addressed-deduplicated-immutable + §registry-table-maps-name-version-to-CAS-hash + §no-node_modules-directory-is-ever-created.

§Borrowable-pattern: §when-replacing-an-existing-substrate, §enumerate-the-existing-substrate's-prerequisites-and-eliminate-each-one. §The-replacement-design-IS-the-substitution; §the-substitution-IS-defined-by-what-it-removes.

## §Two-table-SQLite-schema

```sql
CREATE TABLE packages (
    name TEXT NOT NULL,
    version TEXT NOT NULL,
    hash TEXT NOT NULL,          -- CAS hash of package tree
    integrity TEXT,              -- npm integrity field (sha512)
    fetched_at INTEGER NOT NULL, -- Unix timestamp
    PRIMARY KEY (name, version)
);

CREATE TABLE package_meta (
    name TEXT PRIMARY KEY,
    versions_json TEXT NOT NULL, -- Cached registry metadata
    fetched_at INTEGER NOT NULL
);
```

§Two-named-tables:
- **`packages`** — `(name, version)` → `hash` (CAS tree hash) + `integrity` (npm sha512) + `fetched_at`.
- **`package_meta`** — `name` → `versions_json` (cached registry metadata) + `fetched_at`.

§Two-different-cache-shapes: §per-version-row in `packages` + §per-package-row in `package_meta`. §The-`package_meta`-table-caches-the-npm-registry's-version-listing-avoiding-repeated-HTTP-requests-during-a-single-resolution-pass.

§Borrowable-pattern: §two-tables-for-two-different-cache-grains (per-version + per-package) — §the-design-uses-a-coarser-cache-for-metadata + §a-finer-cache-for-content.

§Sibling to cycle 221 @endo/bundle-source's §SHA-512-content-addressed-source-map-cache with §two-parallel-directory-structures — both designs §two-layered-caches-with-different-grains. §Two-different-substrates (SQLite tables vs filesystem directories) but §same-discipline.

## §Go-style-Minimal-Version-Selection (MVS)

> Inspired by Go's module system, version resolution uses **Minimal Version Selection (MVS)** adapted for npm's semver conventions.

§The-key-philosophical-departure-from-npm. §Borrowable-pattern: §pick-the-version-that-was-explicitly-required + §avoid-untested-upgrades.

The §four-step-algorithm:

1. §Collect-requirements (recursive walk of `dependencies` in `package.json`).
2. §For-each-package-group-by-major-version + §find-the-greatest-minor.patch-explicitly-mentioned-that-satisfies-all-declared-ranges. §The-`greatest-explicitly-mentioned-minor-version`-rule — §never-select-a-version-newer-than-what-any-package-in-the-dependency-graph-has-declared; §this-is-conservative — §it-avoids-pulling-in-untested-versions.
3. §Co-versioned-workspaces — workspaces resolved to the same version (matches monorepo convention of lockstep publishing).
4. §Resolve-transitively — re-walk the dependency graph with selected versions; repeat until stable (typically 1-2 iterations).

### §Comparison-with-Go's-MVS table

```
| Aspect                  | Go MVS                  | Endor MVS                                |
|-------------------------|-------------------------|------------------------------------------|
| Version format          | semver                  | semver                                   |
| Selection rule          | Greatest mentioned      | Greatest mentioned minor within major    |
| Major version coexistence | Yes (import paths differ) | Yes (compartment map allows multiple major versions) |
| Lock file               | go.sum (verification)   | Registry table (cache)                   |
| Network fetch           | On demand               | On demand                                |
```

§Five-aspects-named-side-by-side. §Borrowable-pattern: §comparison-with-a-named-precedent-system-via-table (Go MVS, npm's MVS-equivalent, etc.). §The-table-IS-the-justification-for-the-design-decisions.

§Borrowable-pattern: §when-the-design-is-inspired-by-a-named-precedent, §a-side-by-side-table-makes-the-similarities-and-differences-explicit.

## §Six-step-package-fetching-pipeline

```
1. Fetch metadata.    GET registry.npmjs.org/{name}
2. Select version.    From cached metadata, match resolved requirement.
3. Fetch tarball.     GET dist.tarball
4. Verify integrity.  Check dist.integrity (SHA-512) against tarball.
5. Extract to CAS.    Strip 'package/' prefix; CAS-blob each file; build tree entry; CAS-tree the tree.
6. Update registry table.  Insert (name, version, tree_hash, integrity).
```

§Six-named-steps with §the-strip-`package/`-prefix detail — npm tarballs are §gzipped-tar-archives-with-a-`package/`-prefix. §Borrowable-pattern: §when-extracting-a-package-format, §strip-the-known-prefix + §store-each-file-content-addressed + §build-the-tree-entry.

§The-integrity-check-step is §SHA-512-vs-npm's-`dist.integrity` — §sibling to cycle 221 @endo/bundle-source's §endoZipBase64Sha512-integrity-hash. §Two-cycles-with-SHA-512-as-integrity-anchor.

## §Six-step-integration-with-`endor run`

```
When `endor run entry.js` encounters an `import` of a bare specifier:
1. Look up in entry package's dependencies.
2. Resolve the version using MVS.
3. Check registry table for resolved version.
4. If missing, fetch from npm + store in CAS.
5. Read package.json from CAS tree.
6. Continue the transitive walk.
```

§Six-step-bare-specifier-resolution flow. §Borrowable-pattern: §the-design-document-traces-the-end-to-end-flow-from-the-user-action-to-the-CAS-load.

## §Offline-mode + §registry-table-as-implicit-lock-file

```
When `--offline` is passed to `endor run`, the registry is not consulted.
The registry table serves as a lightweight lock file: once populated,
subsequent runs resolve to the same versions without network access.
```

§The-registry-table-doubles-as-a-lock-file (§implicit-lock-file). §Borrowable-pattern: §when-the-cache-also-records-version-selections, §it-doubles-as-a-lock-file + §`--offline`-makes-this-explicit.

## §CAS-tree-structure

```json
{
  "entries": {
    "package.json": { "type": "blob", "hash": "sha256:...", "size": 1234 },
    "index.js": { "type": "blob", "hash": "sha256:...", "size": 5678 },
    "lib": { "type": "tree", "hash": "sha256:..." }
  }
}
```

§Recursive-tree-structure with §three-named-fields-per-entry (type + hash + size). §Borrowable-pattern: §each-tree-entry-has-type-hash-size + §`type`-field-discriminates-blob-vs-tree + §recursive-trees-without-special-prefix-paths.

§Automatic-deduplication-at-blob-level — §packages-that-share-files (e.g., vendored copies of the same utility) §automatically-deduplicate-at-the-blob-level. §The-deduplication-is-a-property-of-the-content-addressing + §not-a-separate-optimization-step.

## §Five-Design-decisions with §named-rationale-per-decision

```
1. Go-style MVS, not npm's maximal version selection.
2. SQLite for the registry table.
3. No `node_modules` directory.
4. On-demand fetching, not upfront install.
5. Registry table as implicit lock file.
```
