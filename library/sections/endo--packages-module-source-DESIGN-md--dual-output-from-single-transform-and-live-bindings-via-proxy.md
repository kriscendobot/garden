The 207-line `DESIGN.md` at the root of @endo/module-source explains how ESM source becomes executable in a non-native module system. The single most structurally interesting move sits in the workflow on lines 9-11: "analyze the module source, link with other modules based on the static record's metadata, evaluate the functor, call the functor with linkage." The same `analyze()` call produces TWO output halves at once. The first half is a metadata RECORD: imports, exports, liveExportMap, fixedExportMap, exportAlls. The second half is an executable PROGRAM: the functor source, a JS string that when evaluated yields a function that runs the module body. The compartment-mapper consumes both — the record to link, the functor to execute. §the-named-dual-output-from-single-transform names the move; §the-named-static-analysis-and-functor-paired-output names the tier-3 meta-pattern. The separation-of-concerns from cycle 371's compartment-mapper (lazy-loader-eager-runner-pair) composes upward from this transformation primitive. The three-phase pipeline is explicit. §the-named-three-phase-module-execution names the workflow: analyze, link, evaluate-and-call. §the-named-analyze-link-evaluate-pipeline names the tier-3 meta-pattern. Each phase has a separate output type; the pipeline can be paused between phases (which is exactly what the compartment-mapper's archive form does to enable hash-checking without execution, per cycle 371). The non-trivial implementation move is the live-binding mechanism. Lines 129-131 read: "we depend on the evaluator to put a Proxy on the scope chain to intercept the assignment and effect an update to all modules that import the value." JavaScript ESM live bindings — the feature where `import x` automatically reflects later changes to `x` in the exporting module — are implemented via Proxy-based scope-chain interception. §the-named-live-bindings-via-Proxy-on-scope-chain names the design; §the-named-Proxy-as-live-binding-intercept names the tier-3 meta-pattern. This is the non-trivial mechanism behind a feature ESM users take for granted, and seeing it written out makes clear why the transformation needs the SetProxyTrap signal in the export map.
