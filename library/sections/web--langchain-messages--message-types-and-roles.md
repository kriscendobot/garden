Abstract: Messages are LangChain's fundamental unit of model context — they represent the input and output of a model and carry the conversational state. Each message has a **role** (the message type), **content** (text, images, audio, documents), and optional **metadata** (response info, IDs, token usage). LangChain provides a single standard message type that works across every provider, so behavior is consistent regardless of the model called. The four core types are `SystemMessage` (instructions that prime behavior), `HumanMessage` (user input, possibly multimodal), `AIMessage` (the model's output — text, tool calls, reasoning, and metadata), and `ToolMessage` (the result of one tool execution, matched to its call by `tool_call_id`). Inputs can be given three ways: a bare string (shorthand for a single `HumanMessage`), a list of message objects, or OpenAI-style `{"role", "content"}` dictionaries.

## Basic usage

The simplest use is to create message objects and pass them to a model on invocation. Three input formats are interchangeable:

- **Text prompt** — a plain string, ideal for a single standalone request with no history: `model.invoke("Write a haiku about spring")`.
- **Message prompts** — a list of message objects (`SystemMessage`, `HumanMessage`, `AIMessage`), for multi-turn conversations, multimodal content, or system instructions.
- **Dictionary format** — OpenAI chat-completions style: `{"role": "system", "content": "..."}`.

```python
from langchain.messages import SystemMessage, HumanMessage, AIMessage

messages = [
    SystemMessage("You are a poetry expert"),
    HumanMessage("Write a haiku about spring"),
    AIMessage("Cherry blossoms bloom..."),
]
response = model.invoke(messages)  # Returns AIMessage
```

## Message types

### System message

A `SystemMessage` is an initial set of instructions that primes the model's behavior — sets tone, defines the model's role, and establishes response guidelines.

### Human message

A `HumanMessage` represents user input. It can contain text plus any multimodal content (images, audio, files). A bare string passed to `invoke` is shorthand for a single `HumanMessage`. Optional metadata fields include `name` (to identify different users — behavior varies by provider) and `id` (for tracing).

### AI message

An `AIMessage` is the output of a model invocation. It carries text, tool calls, reasoning, multimodal data, and provider-specific metadata. You can also construct one manually and insert it into history as if the model produced it (useful because providers weigh message types differently). Key attributes:

- `text` / `content` — the text, or the raw (string or list-of-dict) content.
- `content_blocks` — the standardized content-block representation (see the companion section).
- `tool_calls` — tool calls the model made (`name`, `args`, `id`); empty if none.
- `id` — unique identifier (generated by LangChain or returned by the provider).
- `usage_metadata` — token counts when available (`input_tokens`, `output_tokens`, `total_tokens`, plus detail breakdowns including `reasoning` and `cache_read`).
- `response_metadata` — provider response metadata.

During streaming you receive `AIMessageChunk` objects that **sum** into a full message (`full = full + chunk if full else chunk`).

### Tool message

A `ToolMessage` passes the result of a single tool execution back to the model. Required fields: `content` (the stringified tool output), `tool_call_id` (must match the `id` of the originating tool call in the `AIMessage`), and `name` (the tool's name). An optional `artifact` field stores supplementary data that is **not** sent to the model but is accessible programmatically — useful for raw results, debugging data, or retrieval metadata (for example a `document_id` and `page` alongside the human-readable passage).

```python
ai_message = AIMessage(content=[], tool_calls=[
    {"name": "get_weather", "args": {"location": "San Francisco"}, "id": "call_123"},
])
tool_message = ToolMessage(content="Sunny, 72°F", tool_call_id="call_123")
messages = [HumanMessage("What's the weather in San Francisco?"), ai_message, tool_message]
response = model.invoke(messages)
```

Most providers require that an `assistant` message with tool calls be followed by the corresponding `tool` result messages, and some require history to start with a `user` message — constraints that matter when trimming or deleting messages (see `web--langchain-short-term-memory--context-management-and-state-access`).
