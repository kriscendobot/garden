E's taxonomy of *reference* sameness — the synchronous `==` predicate (mutually recursive with [object sameness](../sections/web--miller-equality-object-sameness--overview.md), whose base cases ground it). For any references `x` and `y`, `x == y` immediately either returns `true`, returns `false`, or **throws**. If both are **Settled**, it must return `true` or `false`; therefore if it throws, at least one operand was Unsettled. When the sameness formulas are the same, `==` returns `true` and the references are **designationally equivalent**; when both are Settled and their ground formulas are the same, they *designate the same object*; if the formulas differ, they designate different objects and `==` returns `false`. The predicate is **monotonic**: once it returns an answer for a pair (rather than throwing), it always returns that same answer — an Unsettled reference usually lacks enough information to predict the Settled answer, which is exactly why `==` may decline to answer (throw) on Unsettled operands. A reference transitions Unsettled → Settled (never back). E's hashtable abstraction **EMap requires Settled keys**: an Unsettled reference used as a key throws rather than being accepted, because EMap needs the stability that monotonic `==` over Settled references provides.

For any references `x` and `y`, `x == y` immediately (synchronously) either returns `true`, returns `false`, or throws an Exception. If `x` and `y` are both Settled, then `==` must return either `true` or `false`. Therefore, if it throws, then at least one of the two operands was Unsettled at the time. If the sameness formulas of `x` and `y` are the same, then `x == y` returns `true` and we say they are **designationally equivalent**. If `x` and `y` are both Settled (i.e., their sameness formulas are ground — they contain no unbound variables, i.e., their sameness identity does not depend on any promises), then if their sameness formulas are the same, they *designate the same object*. If the sameness formulas of two Settled references are different, they designate different objects and `x == y` returns `false`.

The `==` predicate is **monotonic**, meaning that once it returns an answer for a pair of operands (rather than throwing), it will always return that same answer for the same pair. Unsettled references don't normally provide enough information to determine what the answer will be once they're Settled, which is why `==` needs the option of not answering when the operands are Unsettled. As shown in the state-transition diagram, a reference can transition from Unsettled to Settled, but once Settled, always Settled.

E's built-in hashtable-based collection abstraction, **EMap**, requires Settled keys. If an attempt is made to use an Unsettled reference as a key, it will throw an Exception rather than accept the key.

In terms of sameness formulas: `x == y` is `true` when they are the same formulas. It is `false` when the two formulas are such that no possible substitution of values for their respective variables could make them the same (the formulas could not be unified). When the formulas are not currently the same but may or may not become the same based on future substitutions, then `x == y` throws. Each **Promise** (unresolved reference) is a logic variable; when a promise resolves, all occurrences of it are (as if) replaced by what it resolves to. A reference is Settled exactly when its sameness formula contains no unbound logic variables. An **Unconnected** reference corresponds to a logic variable known to never resolve further (its precise sameness semantics are flagged as undecided on the source).

The page also notes the **designational vs computational equivalence** distinction via the **Disconnected** reference: a Disconnected reference (a former Far reference broken by partition) keeps the sameness identity it had as a Far reference — so it still *designates* its target object even though it no longer conveys authority to invoke it. Because of this, `==` tests *designational* equivalence rather than *computational* equivalence. A **PowerKey** wraps a possibly-unsettled base reference so it can be used as an EMap key; it is named by analogy to a powerset over the base reference-as-key, and a CycleBreaker variant reports a stable hashCode so it can safely key the built-in hashtables even while walking cyclic/unsettled structures. (The source marks the PowerKey/CycleBreaker details and the "answer-true-on-Unsettled-when-provable" relaxation as partly stale notes pending a spec tightening that would require both operands be Settled, like EMap keys.)
