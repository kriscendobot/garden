§1 frames the problem: in scenarios such as web programming where code is linked together from multiple sources, **object capability patterns (OCPs)** provide an essential safeguard, enabling programmers to protect the private state of their objects from corruption by unknown and untrusted code. *However, the benefits of OCPs in terms of program verification have never been properly formalized.* The paper develops **OCPL** — *the first program logic for compositionally specifying and verifying OCPs in a language with closures, mutable state, and concurrency*. The key idea: OCPL accounts for the interface between verified and untrusted code by adopting a *well-known idea from the literature on security protocol verification* — namely *robust safety*. *Programs that export properly wrapped values to their environment can be proven robustly safe, meaning that their untrusted environment cannot violate their internal invariants.* The §1 motivating example is the *readonly* wrapper: `readonly ≜ λr. λ_. !r` and `w ≜ readonly ℓ` — a function that wraps a reference `ℓ` so untrusted code can read but not write. The §1 *low-integrity-value* concept (or *low value* for short, adapted from Abadi 1999) is the central technical device: a low value is *a value that can be safely shared with untrusted code*, *a value from which no code can possibly extract a direct reference to private state*. Formalized as a logical relation using Iris's built-in support for guarded recursive predicates. **§2 Robust Safety and OCPL** defines the formal foundations. **§2.1 HLA** (Higher-order, with Locations and Assertions) is the programming language: a call-by-value λ-calculus with recursive functions, products, sums, references, fork-based concurrency, and *assertion expressions* (`assert e` evaluates `e`; if false, sets a *goodness bit* in the machine state to `Fail`). **§2.2 OCPL** is the program logic built on Iris (concurrent separation logic). Hoare triples come in two flavors: *progressive* (the expression does not get stuck) and *non-progressive* (no progress guarantee — useful for code that may legitimately get stuck due to dynamic type errors introduced by untrusted code). OCPL divides memory locations into *high-integrity* (private to verified code) and *low-integrity* (freely shared with untrusted code). The `lift Ψ` operator (Fig. 3) lifts a *predicate-on-locations* Ψ to a *predicate-on-values* — recursively defined: `lift Ψ ℓ ≜ Ψ ℓ`; `lift Ψ (v_1, v_2) ≜ (lift Ψ v_1 ∗ lift Ψ v_2)`; for function values, `lift Ψ (rec f x. e) ≜ ▷∀v. {lift Ψ v} e[v/x, rec f x. e/f] {y. lift Ψ y}_?` (non-progressive triple under the *later* modality). **§2.3 Metatheory**: two key metatheorems both mechanically verified in Coq. **AdequacySafety**: an expression verified with a progressive triple `{T} e {x. T}_p` when run from a good initial state yields a final state with `g' = OK` (no failed assertions). **RobustSafety**: for any *adversarial context* `C ∈ AdvCtx` (HLA contexts containing neither locations nor assertions), an expression `e` verified to return only low values stays good even when linked into `C[e]` — *verified user code can be linked with untrusted code, while remaining safe (i.e., its internal assertion statements will never assert false)*.
