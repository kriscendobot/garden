§3 takes the §2 worked example out of the lab and into the contemporary Web. **§3.1 Cross-Site Request Forgery (CSRF)** maps the compilation-scenario Confused Deputy attack onto a stock-broker Web application: the Vendor is the stock broker; the User is the attacker's victim (a logged-in customer); the Compiler is the Web browser; the attack vehicle is an HTML FORM on an attacker-controlled page that submits a buy-request to the broker's purchase URL using the victim's session cookies. Table 3 displays the explicit element-for-element mapping across three scenarios (compilation, CSRF, clickjacking). The CSRF paper's [16] mitigation — *unguessable tokens in the HTML FORM* — is structurally equivalent to *transitioning the application away from the ACL model and to the capability model*; the unguessable token is the *web-key* (per §3.2.1's [4] paper *web-key: Mashing with Permission*). **§3.2 Clickjacking** transitions the *click-on-a-button* request through the same diagnosis: an attacker frames the victim's portfolio page in a transparent iframe and positions an inviting target underneath the *Close Position* button so the user's click sells their holdings. The §3.2 paper observes that *underneath the IFRAME, the attacker's page puts content that entices the user to click at a specific location*; the underlying problem is the same — a Confused Deputy attack where the Browser is the deputy, the cookie is the message-sender identifier, and the clickjacking attacker controls the *targeting* of the message. **§3.2.1 web-key** is the canonical fix: *unguessable URLs* are *capabilities-by-reference* for Web resources; *no changes to Web protocols, formats, user agents or server-side infrastructure are required to make this transition* — the required changes are *limited to the URL namespace defined by a Web application*. The §3.3 *Click fraud* extends the diagnosis to online advertising: *little can be reliably concluded based on client authentication* — knowing *who* sent a click does not tell you *whether the click was intended*. The §4 *Related Work* names Norm Hardy's 1988 *Confused Deputy* [8] as the originating publication, Chris Shiflett's 2004 *CSRF* coinage, and Miller et al's 2003 *Capability Myths Demolished* [11] as the prior theoretical elaboration. §4 also names the *core contribution of this paper*: *the description of the Confused Deputy problem in the terminology of the access matrix; this description clarifies how the ACL and capability models produce contradictory access decisions, thus providing a more exact characterization of the Confused Deputy problem.* The §5 *Conclusion* names the migration path: *in messaging scenarios involving more than two principals, the ACL model fails to retain enough information to enable correct access decisions. These errors in the model are manifested in all systems that use the ACL model for access control in multi-party scenarios. ... The capability model does not have these logic errors and can effectively control access in multi-party scenarios. Some systems, such as the Web, can be converted from the ACL model to the capability model without change to their infrastructure and with relatively minor changes to applications.*
