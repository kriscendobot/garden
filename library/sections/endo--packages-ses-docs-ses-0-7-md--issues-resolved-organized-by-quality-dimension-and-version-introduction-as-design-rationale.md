@endo/ses docs/ses-0.7.md is a 64-line version-introduction document published 2020-03-10 by Kris Kowal at SES 0.7's release. The doc is the FIRST conformant single-body section doc authored after the cycle 352-followup systematic refactor (which transformed 867 multi-section docs into 5,450 frontmatter-plus-single-body files). Cycle 353 is the forty-fourth consecutive non-garden source after the pivot (310-353), continuing §forty-four-cycles-with-named-pivot-domain-stay. The doc's single most structurally interesting move is §the-named-issues-resolved-organized-by-quality-dimension: the release notes organize resolved issues into FOUR named quality dimensions — Security, Completeness, Testing, Development — rather than by feature category or chronology. Tier-3 framing: a version-introduction document can use the quality-attributes-being-improved as its primary organization axis, since release notes are about CHANGES TO QUALITY rather than additions of features. §the-named-four-quality-dimensions-security-completeness-testing-development is the canonical organization for SES 0.7's release-notes shape. §the-named-version-introduction-as-design-rationale — first-explicit-observation as a tier-3 meta-pattern. The doc reads less like a CHANGELOG (chronological list of fixes) and more like a DESIGN RATIONALE (why each change improves a named quality dimension). Each bulleted item ties to a quality dimension; some name the SOURCE of the prior degradation explicitly. §the-named-removed-dependency-as-named-improvement — the Security section names TWO removed dependencies (the Realms shim + the esm package) each as a security improvement because the removal eliminates a class of vulnerability or side-effect. §the-named-realms-shim-removal-as-named-milestone — first-explicit-observation. SES 0.7 introduced the simpler `lockdown()` + `harden()` + `Compartment()` API specifically because the prior Realms-shim-dependent API exposed cross-realm leaks. §the-named-esm-package-removed-because-side-effects — first-explicit-observation. The doc names THREE specific side-effects of the esm package (*"transpiles code, alters globals, and proxies module namespaces"*) — each of which compromises hardening. The discipline: when removing a dependency, name the specific harms it caused so future contributors don't reintroduce them. §the-named-whitelist-runs-last-detect-shim-errors — the Completeness section names a STRUCTURAL ORDERING discipline (*"Whitelist on intrinsics runs last: Detect errors in shims"*). Running the whitelist last means shim bugs cause the whitelist to FAIL LOUDLY rather than silently masking the shim error. Compare to cycle 337's §the-named-helpful-stack-on-misuse — both are runtime-detection-of-discipline-violations patterns; cycle 353 reveals the ORDERING-DISCIPLINE variant (last-step verification catches errors from prior steps). §the-named-code-quality-metrics-named-explicitly — the Development section enumerates concrete metrics: complexity bound of 8, max lines per module of 300, lint rules for unused ad-hoc rules. §the-named-complexity-eight-max-lines-three-hundred — first-explicit-observation. The metrics are NUMERIC and ENFORCEABLE (not just guidelines) — a complexity score above 8 or a module above 300 lines is a lint failure. Tier-3 framing: when a code-quality discipline is to be enforced, name SPECIFIC NUMERIC THRESHOLDS so the discipline is machine-checkable. §the-named-test262-runner-packages-as-named-tooling — *"Added test262 runner packages: Declarative test selection. Used by many packages."* The doc NAMES that SES added test262 runner packages for declarative selection and that they were ADOPTED across the monorepo. The §multi-package-adoption-as-validation discipline — naming WHO ELSE uses a tool is evidence of its utility. §the-named-tape-to-tap-migration-with-named-rationale — TAP migration named with FOUR specific reasons (better skip count + more stable + parallelization + separate realms per suite). When migrating between tools, name the specific advantages so future contributors understand the choice. §the-named-monorepo-as-named-architecture — the Development section names monorepo + Lerna + workspace structure as architectural choices, with the rationale *"More granular, smaller, single-purpose packages (better division of concerns)"*. §the-named-node-version-cut-as-major-version-boundary — the doc names *"Removed support for node < 13"* as a Development improvement. Major version boundaries cut support for older runtimes; the cut is the named license for adopting newer JS features (here: globalThis). §the-named-globalThis-adoption-replaces-return-this — *"Make use of globalThis (removed all evaluation of \"return this\")"*. The old idiom for getting the global was `Function('return this')()` which IS an evaluator call; `globalThis` is the standardized replacement that doesn't require eval. The eval-free global access is the security improvement that allows SES to NOT have to suppress this particular evaluator path.
