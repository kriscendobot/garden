Abstract: OpenAI's engineering post introducing **Symphony**, an open-source agent orchestrator that turns a project-management board (Linear) into a control plane for coding agents: every open task gets a dedicated agent, agents run continuously, and humans review the results. Symphony grew out of a team decision to build a repository with no human-written code (every line generated by Codex), which exposed a new bottleneck once the code-generation problem was solved: **context switching** between many interactive agent sessions. Symphony is distributed as a single `SPEC.md` and reportedly produced a 500% increase in landed pull requests on some teams. This overview frames the problem, the shift to ticket-driven orchestration, and the headline outcome; the sibling sections cover the motivation, the model, the outcomes, the lessons, and the embedded specification.

Six months before the post, while working on an internal productivity tool, the team made a then-controversial decision: build their repo with **no human-written code** — every line generated by Codex. To make that work they redesigned their engineering workflow from the ground up: an agent-friendly repository, heavy investment in automated tests and guardrails, and treating Codex as a full-fledged teammate (documented in a prior "harness engineering" post). It worked, but surfaced the next bottleneck: **context switching**.

To solve that, the team built **Symphony** — an agent orchestrator that turns a project-management board like Linear into a control plane for coding agents. Every open task gets an agent, agents run continuously, and humans review the results. The post reports a **500% increase in landed pull requests** on some teams in the first three weeks, and explains how to turn any issue tracker into an always-on agent orchestrator.

Symphony is authored by Alex Kotliarskyi, Victor Zhu, and Zach Brock (OpenAI, Engineering, April 27, 2026). It is deliberately a **reference implementation** distributed as an `SPEC.md`, not a maintained product; the reference implementation is written in Elixir for its concurrency primitives, and the authors encourage readers to point their own coding agent at the spec and generate a tailored implementation.

> The garden runs a structurally similar system: a git-backed job board (the `journal2` branch) where autonomous **gardener** workers race to claim posted jobs, an **orchestrator** role that decomposes multi-part work, and per-job worktrees that isolate each claim. Symphony is an independent convergent design worth reading against the garden's own; see the [`agent-fleet-orchestration`](../topics/agent-fleet-orchestration.md) topic for where the two genuinely meet and where they diverge (central orchestrator authority vs decentralized push-CAS claim).
