§3 defines SES_light formally with a small-step operational semantics: Figure 2 lists the syntax (a comma-separated list of terms; Loc / Val / Vars / Stmts as locations / values / user-variables / user-statements; annotations like `$All`, `$Num`, `$Native` for property-lookup precision); Figure 3 lists Heaps and Stacks (Heap maps Loc to Object; Stack is a list of Records; activation records have writable/configurable/enumerable attributes on properties). The operational semantics is *standard-store-model-no-prototype-on-scope-objects*; this differs from the Maffeis-Mitchell-Taly 2008 [22] semantics, which modeled scope objects as first-class. The simplification is *possible due to the more standard scoping semantics of ES5S*. §4 *The API Confinement Problem for SES_light* sets up the formal framework: the *labeled semantics* attaches unique labels (allocation-site labels) to all nodes in the syntax tree of a SES_light term; labels are also attached to heap locations and stack frames *based on the term whose evaluation created them*. **Theorem 1 (Renaming preserves bisimilarity)**: for all wellformed states *S*, `Rn(Tr(S)) = Tr(Rn(S))` — α-renaming bound variables produces a bisimilar trace. The *API confinement* property is then formalized via the *PtsTo* (points-to) and *Reach* (state-reachability) operators. **Definition 4 (Confinement Property)**: a trusted service `t` *safely encapsulates* a set of property-allocation-site labels `P` iff `PtsTo(un, Reach(S_0(t))) ∩ P = ∅` — denoted `Confine(t, P)`. The `un` variable is the *forbidden-object test variable* that untrusted code uses to attempt to store a reference to a forbidden object; the property says *no execution path causes `un` to ever point at one of the forbidden labels*. §5 *Analysis Procedure* defines a *flow-insensitive context-insensitive Datalog-based points-to analysis* — adopting the inclusion-based approach of Whaley et al [40] and expressing the analysis in Datalog. The procedure D(t, P): (1) **collect facts** about the statements in `t` and add them to a Database (including facts about the initial heap and the term `var un; eval(s, "un", "api")` for all s ∈ SES_light); (2) **conservatively encode the SES_light semantics** in the form of Datalog inference rules and compute the consequence set; (3) **analyze the database for confinement-violating facts**. Figure 4 lists the Datalog relations (programs: Assign, Load, Store, Throw, Catch, Global, FormalArg, Annotation, etc.; heap/stack: Heap, Prototype, Stack). Figure 6 lists the 14 inference rules R (`ASSIGN`, `LOAD`, `STORE1`/`2`/`3`, `ANNOTATION`, `TP1`/`2`, `ACTUAL1`/`2`/`3`, `PROTOTYPE1`/`2`/`3`, `GLOBAL1`/`2`, `THROW`). **Theorem 2 (Soundness)**: *for all terms t and forbidden allocation-site labels P, D(t, P) ⟹ Confine(t, P)*. The proof goes by three lemmas: (1) the encoding `Enc` of a set of states safely over-approximates the encoding of the set of reachable states from it; (2) the initial facts `F_0(t)` over-approximate the encoding of `S_0(t)`; (3) the abstract points-to `PtsTo_D` safely over-approximates the concrete `PtsTo` under the encoding. The procedure D(t, P) is *decidable* — the maps `Enc_T`, `Cons` (consequence-closure of Datalog rules), and `PtsTo_D` are all computable.
