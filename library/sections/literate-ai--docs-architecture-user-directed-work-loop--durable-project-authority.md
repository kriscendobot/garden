> Abstract: User direction becomes an evidence-gated durable work item before implementation, with a reasoned conclusion, owner, dependencies, subtasks, and completion evidence; reusable lessons update the narrowest authority while private runtime details and one-off model mistakes stay out of permanent instructions.

The work loop inspects existing authority, records the requested outcome and the narrowest owning Component, Flavor, skill, workflow, routing policy, documentation area, or framework rule, then implements in dependency order. Build, test, run, or review evidence either returns the item to active work or supports a narrow authority update, changelog entry, and checked item in Git history.

The queue is intentionally compact. Detailed designs remain in linked roadmap documents, and Git supplies history instead of a parallel timestamped ledger. Secrets, credentials, worker hostnames, and raw private prompt journals are excluded; durable work records portable evidence requirements and report identities only.
