> Inspired by Go's module system, version resolution uses **Minimal Version Selection (MVS)** adapted for npm's semver conventions.

§The-key-philosophical-departure-from-npm. §Borrowable-pattern: §pick-the-version-that-was-explicitly-required + §avoid-untested-upgrades.

The §four-step-algorithm:

1. §Collect-requirements (recursive walk of `dependencies` in `package.json`).
2. §For-each-package-group-by-major-version + §find-the-greatest-minor.patch-explicitly-mentioned-that-satisfies-all-declared-ranges. §The-`greatest-explicitly-mentioned-minor-version`-rule — §never-select-a-version-newer-than-what-any-package-in-the-dependency-graph-has-declared; §this-is-conservative — §it-avoids-pulling-in-untested-versions.
3. §Co-versioned-workspaces — workspaces resolved to the same version (matches monorepo convention of lockstep publishing).
4. §Resolve-transitively — re-walk the dependency graph with selected versions; repeat until stable (typically 1-2 iterations).

### §Comparison-with-Go's-MVS table

```
| Aspect                  | Go MVS                  | Endor MVS                                |
|-------------------------|-------------------------|------------------------------------------|
| Version format          | semver                  | semver                                   |
| Selection rule          | Greatest mentioned      | Greatest mentioned minor within major    |
| Major version coexistence | Yes (import paths differ) | Yes (compartment map allows multiple major versions) |
| Lock file               | go.sum (verification)   | Registry table (cache)                   |
| Network fetch           | On demand               | On demand                                |
```
