The 166-line providers/anthropic.js is the Anthropic API provider for @endo/lal and the tenth lal-package artifact in the cluster. Cycle 408's most structurally interesting move surfaces a previously-unnamed asymmetry at the provider boundary. §the-named-tool-result-mapped-to-user-role-with-tool_result-block names the observation. The common format defined in agent.types.d.ts has FOUR roles for ChatMessage: `'system' | 'user' | 'assistant' | 'tool'`. Anthropic's API has THREE roles: system (top-level string), user, and assistant. The fourth role — tool — does not exist in Anthropic's vocabulary. So the provider FOLDS the tool role into the user role at lines 77-89: when `msg.role === 'tool'`, it pushes `{ role: 'user', content: [{ type: 'tool_result', tool_use_id: toolUseId, content: msg.content }] }`. Same conceptual operation (returning a tool result), different message structure per API. The content block shape is dictated by Anthropic. §the-named-content-block-type-discrimination marks lines 145-157.
