The 773-line README for @endo/compartment-mapper is the central architectural workhorse of the Endo ecosystem. The package's job is to build compartment maps for Node.js applications by finding their dependencies and describing how to create a Compartment for each package, then to emit the resulting map in one of four output forms depending on deployment target. The package was previously in the pivot cluster via cycle 235's generic-graph.md ingest at the dependency-resolution substrate level; cycle 371 ingests the README at the design level and reveals the package's structural center. The single most structurally interesting move is on line 47: "The compartment mapper is also not coupled specifically to Node.js IO and does not import any powerful modules like `fs`. The caller must provide read powers in the first argument as either a ReadPowers object or as a standalone `read` function." §the-named-caller-supplies-IO-powers-not-package-imports-fs names the move; §the-named-ocap-discipline-applied-to-the-tool-itself names the tier-3 meta-pattern. The package whose JOB is enforcing OCAP discipline on third-party packages applies the same discipline to ITSELF. The mapper is given the I/O capabilities it needs, not allowed to take them. This is the deepest form of dogfooding: the OCAP-enforcement tool that doesn't take OCAP-violating shortcuts. The ReadPowers type at lines 56-67 is itself an interesting structural revelation. Two required fields (`read` and `canonical`) plus four optional fields (`computeSha512`, `fileURLToPath`, `pathToFileURL`, `requireResolve`). The optional fields are not just convenience — each unlocks a specific compatibility feature. computeSha512 enables archive integrity checks. fileURLToPath enables `__dirname` and `__filename` for CJS modules. requireResolve enables `require.resolve()` semantics for CJS modules. The caller is asked to supply exactly the capabilities needed for the features the caller wants. §the-named-ReadPowers-as-typed-capability-bundle names the design; §the-named-optional-capabilities-unlock-features names the tier-3 meta-pattern. The package emits the compartment map in four output forms, each suited to a different deployment target. §the-named-four-output-forms-from-one-mapper names the move; §the-named-deployment-target-as-output-format-axis names the tier-3 meta-pattern. The four forms are LIVE import via `importLocation` (load and execute immediately from the filesystem); ARCHIVE via `writeArchive` (Zip file with `compartment-map.json` manifest, hashable, safely introspectable without execution); SCRIPT bundle via `makeScript` (single string of JavaScript suitable for `eval` or web `<script>`); and FUNCTOR bundle via `makeFunctor` (string that evaluates to a function accepting runtime options for Compartment-confined execution).
