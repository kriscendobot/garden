When a rebase moves a PR's return value into a facet-pair / plain record that crosses a CapTP boundary (endo daemon incarnations), a real integration-test run is mandatory. Both `git` tree-merge and `node --check` pass while an object-passability violation hides until runtime: a CopyRecord whose properties are Remotables cannot ALSO carry a method (e.g. `harden({ scheduler, schedulerControl, handle: () => h })`), which fails marshalling with "cannot serialize Remotables with non-methods like X". The conflict here (#609 Phase 4 changed `interval-scheduler` from a flat `Far(...)` return to a `{ scheduler, schedulerControl }` record) radiated beyond the diff markers into (a) test consumption patterns (`E(host).makeIntervalScheduler()` now returns the record, so callers must destructure `.scheduler`) and (b) that CapTP passability rule, both invisible to tree-merge and syntax checks. The fix relocated the removed method's data (a scheduler mail handle) into a daemon-internal map consulted by the generic `handle` formula maker. Lesson reinforces the existing weaver norm to run affected-package tests, but adds the specific "record-with-method fails CapTP marshalling" tripwire for endo rebases.
