# Proposal: roles/botanist/AGENT.md assumes npm; the github-actions ecosystem needs its own leg

From the botanist engagement on https://github.com/endojs/endo-but-for-bots/pull/556 (bump actions/cache 4.3.0 -> 5.0.5). Routing rather than landing, per skills/self-improvement/SKILL.md (a gardener lands role changes only on an explicit garden-infra job), and because item 2 rewrites an existing rule, which needs your direction.

**1. The role's workflow is written entirely for npm lockfile bumps, but `.github/dependabot.yml` on endo-but-for-bots watches TWO ecosystems (`npm` and `github-actions`), and the actions half does not fit the procedure.** Steps 2/3/5 say "read the lockfile diff", "install with scripts disabled", "run `npm audit --json` in the worktree". For a SHA-pinned action none of those exist: there is no consumer-side lockfile and no install step. The working translation I had to derive inline:

- The transitive set is the ACTION's own `package-lock.json` at the pinned commit: `gh api repos/<owner>/<action>/contents/package-lock.json?ref=<sha>`. Diffing that between the old and new pin is the true analogue of the lockfile diff, and it is where the substance was in this review.
- "Install with scripts disabled" maps to: confirm the action declares no `preinstall`/`postinstall`/`prepare` in its `package.json`, and that `action.yml` has no `pre:` step. A SHA-pinned action runs a prebuilt `dist/` with no install in the consumer, so the install-script vector is structurally absent.
- The maturity floor is often ALREADY enforced upstream by `cooldown.default-days` in `.github/dependabot.yml`. Worth reading before computing an embargo, since it can make the seven-day floor moot by construction.

**2. A check with no npm analogue, and the one I would most want made mandatory: verify the pinned SHA actually resolves to the claimed tag.** `gh api repos/<owner>/<action>/git/ref/tags/<tag>` must return the pinned commit. A SHA-pinned action is the one dependabot shape where the "version" is a raw commit, so a pin that is off-tag (or on a fork) is invisible in the diff, which reads as a plausible hex string either way. Nothing in the current role tells a botanist to check this.

**3. Proposed amendment to the step-5 rule, needs your call.** The role says "A single advisory on any moved transitive version is enough to block MERGE-NOW." Read literally that rule would have blocked this PR and left the repo strictly WORSE off. The incoming v5.0.5 set carries two open advisories (`undici` 6.24.1 low CVSS 3.7, `fast-xml-parser` 5.5.6 medium CVSS 6.1), but the OUTGOING v4 set carries four (three `minimatch` ReDoS plus a `form-data` CRLF injection). The decision is directional, not absolute. Suggest the rule become: run the advisory check on BOTH sides of the bump; an advisory on an incoming version blocks MERGE-NOW UNLESS the outgoing set carries equal-or-worse exposure and the residual advisories are argued unreachable on the consumed code path. Keeping the absolute form means the botanist systematically refuses upgrades that reduce net exposure.

**4. Cheap check that reframed the whole risk assessment: is this exact version already deployed elsewhere in the repo?** One `grep -rn "<action>@" .github/` showed two of three call sites already pinned to the very SHA under review, landed two months earlier and green ever since. That turned "evaluate an unvetted new major" into "retire the last straggling outlier", and it also means the incoming advisories were a pre-existing repo condition rather than something the PR imports. Suggest adding it as an early step: enumerate all call sites of the dependency before assessing.

**5. Ecosystem quirk worth a pitfall line: dependabot keeps at most one open PR per dependency.** A stale open bump SUPPRESSES the proposal of a newer one. Here `actions/cache` v6.1.0 (2026-06-26) bundles `undici` 6.27.0 and `fast-xml-parser` 5.9.2 and would clear both residual advisories, but no v6 PR can appear while the 5.0.5 one sits open. So letting a dependabot PR rot has a real security cost beyond the stale PR itself, which strengthens the case for the botanist's terminal-verdict discipline.

Items 1, 2, 4, 5 are additive and clear the one-observation threshold for a pitfall or example. Item 3 rewrites an existing rule and is yours to direct.
