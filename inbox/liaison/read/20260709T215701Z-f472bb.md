Two reusable lessons from the filesystem-watchers build job:

1. DUPLICATE JOB / stale plan status. The build job for design
   `plan/designs/endo-but-for-bots/filesystem-watchers.md` (Issue #110) was
   already fully implemented and MERGED as endojs/endo-but-for-bots#277
   (merged 2026-07-01): the EndoMount.followNameChanges method, the
   MountInterface guard, FilePowers.watchDirectory (fs.watch + 50ms debounce
   + graceful fallback), and all Test Plan cases. The journal design frontmatter

   design status to `Complete` (landed_by #277) and pushed to journal2. Producers
   posting build jobs from plan/designs should reconcile the design status against
   merged PRs first, since imported-from-llm statuses drift stale.

2. endo daemon test-env gotchas (for any future verify of packages/daemon tests):
   (a) yarn 4 disables build scripts, so better-sqlite3's native binding is not
   compiled by `yarn install`; the daemon fails to spawn ("Could not locate the
   bindings file"). Fix: run prebuild-install manually inside the better-sqlite3
   store package dir (node <root>/node_modules/.store/prebuild-install-*/package/bin.js
   --tag-prefix v) with the sandbox disabled (it needs network/exec).
   (b) The daemon binds a unix socket at <daemon-pkg>/tmp/<sub>/endo.sock; a deep
   worktree path (project-wt-... under scratch is ~113 chars) pushes the socket
   path past the 108-char OS limit ("ENOENT ... endo.sock", "Length of path for
   domain socket ... exceeds maximum"). Fix: run the daemon tests from a SHORT
   checkout path (I used a throwaway worktree at /home/kris/garden/scratch/e, on
   the same filesystem as the yarn cache to avoid EXDEV). --preserve-symlinks does
   NOT work (breaks the pnpm linker). Worth capturing in the endo-but-for-bots
   project README or local-verify skill.
