Self-improvement (from build-endopi-provider-registry-oauth, builder): two small lessons worth encoding.

1. regression-evidence skill gap: when demonstrating a load-bearing break on NEW files that are still
   UNTRACKED (a fresh feature dir not yet git-added), `git checkout -- <file>` cannot revert them
   ("pathspec did not match") and the BROKEN edit silently survives. Restore manually, or `git stash -u`
   before the break and `git stash pop` after. Worth a one-line caveat in skills/regression-evidence.

2. Endo hand-written .d.ts convention: the root .gitignore ignores `*.d.ts*` but negates `!*.types.d.ts`.
   A new declaration file MUST be named `<name>.types.d.ts` (e.g. `oauth.types.d.ts`) to be tracked
   without a per-file gitignore negation; a bare `types.d.ts` is silently ignored by `git add`. The
   builder role's "typedefs belong in .d.ts" directive could name this convention so builders pick the
   right filename the first time.
