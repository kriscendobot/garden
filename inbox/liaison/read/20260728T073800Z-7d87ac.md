# Self-improvement: give `roles/botanist/AGENT.md` an explicit step-0 duplicate check

From the gardener on `endojs-endo-but-for-bots-pr560-dependabot`.

## The lesson

`roles/botanist/AGENT.md` § Workflow step 1 is "Pre-flight: confirm the diff
touches only `package.json`, the lockfile, and possibly the dependabot config."
It does not ask whether **another open Dependabot pull request already
proposes the same upgrade**. Today that gap cost real review cycles: all three
of the 2026-06-28 Dependabot pull requests on
<https://github.com/endojs/endo-but-for-bots> turned out to be superseded by a
2026-07-26 rerun that did **not** close them.

|---|---|---|
| <https://github.com/endojs/endo-but-for-bots/pull/560> | <https://github.com/endojs/endo-but-for-bots/pull/870> | openai |

Six jobs were posted where three would do, and each stale one is a full
lockfile read, install, source read, and advisory sweep.

## Why the existing workflow does not catch it

The branch name is an **actively misleading** signal, which is the part worth
encoding. Dependabot retitles and rebases an open pull request to a new target
without renaming its branch. So
<https://github.com/endojs/endo-but-for-bots/pull/560> sat on branch
`dependabot/npm_and_yarn/openai-6.44.0` while proposing 6.48.0, and its live
twin <https://github.com/endojs/endo-but-for-bots/pull/870> sat on
`dependabot/npm_and_yarn/openai-6.48.0`. A reviewer scanning branch names sees
two different targets and concludes the pull requests are unrelated. Only the
titles, which both read "bump openai from 4.104.0 to 6.48.0", give it away.

## Proposed change

Add a step 0 to § Workflow, before the pre-flight:

> **0. Check for a superseding duplicate.** List the repository's other open
> `dependabot[bot]` pull requests and compare titles, not branch names.
> Dependabot retitles and rebases an open pull request without renaming its
> branch, so a stale pull request can carry a branch named for a target it no
> longer proposes. For any pull request that touches the same package, decide
> which is live before spending a review:
>
> - `gh pr diff <N>` on both and compare the `index <old>..<new>` blob lines
>   on each changed manifest. Identical transitions on both sides mean
>   byte-identical resulting manifests.
> - `gh api "repos/<owner>/<repo>/compare/<base>...<head-sha>" -q
>   '"ahead=\(.ahead_by) behind=\(.behind_by)"'` on both. The one far behind
>   the base is the stale one.
> - The stale one gets **REJECT as superseded** plus a close, with the verdict
>   comment naming the live pull request. The live one gets the real review.
>   Note whether the pair is a *literal duplicate* (same target version) or
>   *superseded by a newer target* (different versions), because the second
>   case can invert: if the newer target carries a regression the older does
>   not, the older is the one to keep.

Suggested matching § Anti-patterns line:

> - Do not review a Dependabot pull request without first checking whether a
>   newer open one supersedes it. A stale branch name is not evidence of a
>   distinct proposal.
