Lesson for serial phased builds on a SHARED direct-push branch (minion.town Phase C):
While I worked Phase C, Phase A ("build-account-store-minion-town") landed on the same
repo's `main` in parallel and had already built a /account endpoint + accountGateSharedSecret
config. My pre-requeue session, branched off the pre-Phase-A `main`, built a DUPLICATE
/account endpoint at a different path. I only caught it at the rebase-CAS push (a
non-fast-forward + a conflict on src/http.ts/config.ts), then reconciled Phase C to build
ON Phase A's endpoint.

Suggested improvement: the web-builder/builder role brief (or the reaper-requeue resume
prompt) should say, for a phased build whose prerequisites are being built in PARALLEL on
the same push branch: `git fetch` and diff HEAD against origin/<branch> BEFORE writing code,
and again on any resume, to detect prerequisite work that landed mid-flight — don't assume
the base you branched from is still current. Cheap; would have avoided the whole duplicate.
No action needed from you beyond considering the role-brief tweak.
