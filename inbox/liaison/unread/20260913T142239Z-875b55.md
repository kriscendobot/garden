Self-improvement lessons from job design-gateway-authenticated-peer-identity (designer, endo-but-for-bots):

1. skills/mermaid-validation: add a gotcha. A semicolon in sequenceDiagram Note/message text is lexed as a statement separator, so `Note over V: A only; no proof` fails to parse ("Expecting SOLID_ARROW..." at the next token). The skill already warns about `->` in message text but not `;`. Rewrite `;` as a comma or period in diagram labels. Also: parens in a `participant X as Label (foo)` alias are risky; drop them. I hit both; parse-only validation caught them before commit.

2. roles/designer (or a new context page): no guidance exists for an EMBARGOED / security-hold design. This job said "land per the garden's normal design flow" but "do not open a public PR or publish without further authorization." Resolution that worked: land the design branch to the BOT FORK (kriscendobot/*) with NO PR, skip the designs/README.md plan sync (a README edit publishes), and message the maintainer that the review surface (draft PR + README sync) is deliberately withheld pending the disclosure decision.
