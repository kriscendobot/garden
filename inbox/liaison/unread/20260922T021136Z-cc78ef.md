Project: `kriscendobot/minion.town`.

Two local-verification parity defects surfaced while opening kriscendobot/minion.town#106:

1. `scripts/jobs/gardening/local-verify.sh` selected Yarn for this npm project even though the repository has `package-lock.json`; its build failed with "package doesn't seem to be present in your lockfile". `GARDEN_YARN=npm` made the full gate pass. `pre-push-gates.sh` already selects npm correctly, so local-verify should share that package-manager selection instead of retaining the Yarn default.
2. The full local gate passed, but CI's amd64 runtime-image contract failed because adding the Agent SDK installed its optional second `claude` binary. The project fix now prunes the optional platform binary and points the SDK at the integrity-checked harness; the repeated amd64 image check is green. This host has no `docker`, so local-verify could not run the repository's Docker image CI legs. The parity contract should either fail loud when a declared image check cannot run or provide a deterministic remote/provisioned equivalent; silently omitting it let a real CI regression through.

These are garden-infrastructure follow-ups, not changes appropriate to the project PR.
