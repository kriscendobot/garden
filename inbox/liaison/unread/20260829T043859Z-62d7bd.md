Self-improvement recommendation for `skills/rebase-before-followup/SKILL.md`: when a PR head is on a fork and its base is on the upstream repository, fetch and rebase onto the PR base repository's remote, not merely the same-named branch on `origin`. On `endojs/endo-but-for-bots#832`, `origin/llm` was five weeks stale while `upstream/llm` was current; rebasing onto the former left the PR conflicting and suppressed CI until a second rebase. Add a pitfall instructing the fixer to resolve `baseRepository`/`baseRefName` from the PR and verify the chosen base SHA against `gh pr view`.
