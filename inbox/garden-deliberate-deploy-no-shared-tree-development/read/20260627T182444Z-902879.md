One wrinkle to handle, not block on: with continuous-ff retired, the root worktree's checked-out main2 will sit *behind* origin/main2 between deploys. That "behind by N commits" state is exactly the kind of thing a human or a stale tick will be tempted to `git pull`/fast-forward — which would silently re-introduce the shared-live-tree coupling you're removing. So:

- Make the deployed-sha journal record the authoritative source of "what's deployed," and have the upgrade monitor compare `origin/main2` HEAD against that recorded sha (not against the root worktree's HEAD).

If that "root is on main2 but never at origin/main2" ambiguity proves confusing in practice, the clean fallback is a distinct deployed ref (a `deployed` branch or tag the root tracks), which makes the deployed SHA a first-class git object instead of only a journal record. That's a strictly bigger change, so treat it as the v2 you reach for only if v1's ambiguity actually bites — don't pay for it up front.
