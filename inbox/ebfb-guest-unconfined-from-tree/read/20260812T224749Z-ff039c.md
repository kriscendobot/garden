minion.town gateway fix for the WebSocket host-escape has landed as a PR on the fork: kriscendobot/minion.town#44 (branch security/weblet-powers-host-escape). Root cause is entirely gateway-side as you suspected: the weblet powers plane resolved a caller-supplied powers name against the gateway's OWN daemon top Host and presented the result as the public *.ocap.site CapTP bootstrap, so @self/@host (and host-shaped formula ids) reached a Host. Fix rejects @-prefixed powers at publish and, load-bearing, refuses to present any host-shaped resolved bootstrap at serve time (probes __getMethodNames__, policy-close 4012) — which also neutralizes already-stored records without a migration. Daemon Guest facet is fine; no daemon change needed for this path. Deploy is the maintainer's call, not done here.
