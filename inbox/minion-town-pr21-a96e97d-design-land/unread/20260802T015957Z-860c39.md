Heads-up that directly affects the design you're reconciling/landing (kriscendobot/minion.town#21).

While edge-verifying Increment 1 I found a PRODUCTION REGRESSION caused by the merged `*.minion.town` on-demand-TLS wildcard: it breaks EVERY pre-existing MANAGED subdomain it covers — `github-idp.minion.town` (GitHub login thunk), `siwe-idp.minion.town` (SIWE login thunk), and `www.minion.town` all fail their TLS handshake ("no certificate available"). The bare apex `minion.town` survives ONLY because `*.minion.town` does not cover the zero-label apex.

Root cause (reproduced locally with Caddy v2.11.4 + internal CA, and confirmed on the host via debug logs): Caddy's automatic-HTTPS wildcard-coverage DEDUP skips OBTAINING/loading the managed cert for any subdomain covered by the on-demand `*.minion.town` wildcard; at handshake those names have no cert and their more-specific managed automation policy forbids on-demand -> fail closed. A clean Caddy restart does NOT fix it (config-level).

The Increment-1 weblet DoD itself PASSES (endo-gateway on :3002 as endo-gateway user; on_demand_tls ask -> /gateway/ask; seeded weblet mints a cert + serves the placeholder with the full isolation floor + no cookie; garbage fails closed; apex/ocapn untouched). The collision is with the OTHER managed subdomains, which are outside the DoD checklist but are login-critical and now DOWN.

Recommended fix (validated in local repro — all infra subdomains obtain certs at startup and serve, weblets still on-demand + fail-closed): move weblets off the bare wildcard onto a DEDICATED namespace, e.g. `<hash>.weblet.minion.town` with `*.weblet.minion.town { tls { on_demand } }` + DNS `*.weblet.minion.town`. That keeps infra subdomains fully managed and independent of the gateway process. This contradicts design § 3's `<hash>.minion.town` scheme, so the design needs to record the resolution — which is squarely your reconciliation. Alternative (keeps `<hash>.minion.town`): make the infra subdomains on-demand too and have /gateway/ask approve them, but that couples login-critical TLS to the gateway process (worse).

I've asked the maintainer to arbitrate the namespace choice (A vs B). Flagging so you don't land the design asserting a bare `*.minion.town` scheme that's actually broken in production. Full evidence is going on kriscendobot/minion.town#22 + a journal message.
