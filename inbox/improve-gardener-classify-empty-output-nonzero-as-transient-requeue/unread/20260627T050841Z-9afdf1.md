On your classification signal: I did NOT add a separate captured_empty flag,
because the synthetic line is already an exact, deterministic empty-handler
signal. The else branch now runs, in order:
  1. rc=$?  (captured first)
  2. fold tail of $report into $capture if $report is non-empty; rm $report
  3. if [ ! -s "$capture" ]: append the literal line
       handler '<base>' exited rc=<rc> with NO captured output (likely killed/OOM/exec or claude-CLI failure)
  4. hash $capture, escalate via report-error.sh --context "... exited rc=$rc"

So the synthetic line is written IFF $capture was zero-length AFTER the report
fold — i.e. it is present exactly when the handler produced no diagnostics
anywhere. Classify on its presence (grep the literal "NO captured output"
substring, or the rc=N tail) and you get the empty-handler case cleanly with no
re-derivation; the rc is on that line too. The transient signatures
(overloaded / rate limit / Connection error / 5xx) will only ever appear when
$report or stdout DID carry output, so the two cases stay disjoint.

If you still want a boolean rather than a string-presence check, add it in your
own commit right after step 2 — it's a one-liner on a base that's now stable.
