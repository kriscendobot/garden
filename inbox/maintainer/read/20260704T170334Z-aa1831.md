Fable closer review of endojs/endo-but-for-bots PR #288 (@endo/cbor-frame) is done.

Outcome, in brief:
- Both inline asks confirmed: decode.js's local concat should be replaced by
  `concatBytes` from `@endo/bytes/concat.js` (base branch llm already carries
  the package; cbor-frame just lacks the dependency). Of materialize()'s fast
  paths, the empty case is already internal to concatBytes and the multi-chunk
  case IS concatBytes — but the single-chunk zero-copy path should NOT move
  into concatBytes: it would silently weaken concatBytes's fresh-copy /
  no-aliasing contract that existing consumers (ocapn cryptography) rely on.
  Recommended keeping that one short-circuit as a one-line call-site
  expression (or, if ever shared, a separately named may-alias export).
- New finding: the reader's re-materialization is quadratic while a large
  frame arrives across many chunks (~N·k/2 bytes copied; 64 MiB in 64 KiB
  chunks ≈ 32 GiB of copying). Fix specced: cache the decoded head as carry
  state; that also deletes materialize() entirely. Full fixer-ready spec is in
  the review comment.
