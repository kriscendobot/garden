# fakecloud fit addendum: the four unverified cells and the SDK license

> Abstract: This addendum resolves the open cells in [fakecloud-aws-emulation-fit](fakecloud-aws-emulation-fit.md) using fakecloud's per-service, SDK, and reference pages, plus a read of the upstream source. (1) **`CancellationReasons` fidelity is confirmed at source level.** `TransactWriteItems` returns one entry per `TransactItems` index, `ConditionalCheckFailed` for the failing item and `None` for the rest, and an upstream e2e test asserts this. minion.town's duplicate-detection branch can therefore be *observed* rather than fabricated. (2) **S3 presigned GET works but is not checked by default.** Signatures are parsed and never validated unless `--verify-sigv4` is on, which then verifies presigned query-string signatures with a ±15-minute skew window. Expiry (`X-Amz-Expires`) enforcement is undocumented. (3) **SSM `SendCommand` does not execute anything.** It is a status timer (Pending, InProgress, Success) with test-side failure injection, and upstream source confirms empty `StandardOutputContent`. The deploy-rehearsal gap is now a confirmed gap, not an unverified one. (4) **`dynamodb:Attributes` and `dynamodb:LeadingKeys` are documented as enforced** under `FAKECLOUD_IAM=strict`. The gap becomes "supported, pending a negative test". (5) **The `fakecloud` npm SDK is AGPL-3.0-or-later** with zero runtime dependencies. Keep using raw HTTP in minion.town's test tier rather than adding it as a devDependency; the raw calls are two lines each. One correction to the parent note: the whole-server reset is `POST /_reset`, not `POST /_fakecloud/reset`. Written 2026-09-28 by `scholar-ingest-fakecloud-dev-services-sdks`. This appends to the parent note and does not rewrite it.

This is a journal-side analysis note. It edits nothing in the minion.town repo. Library citations are relative to this file. Upstream-source citations are pinned to `faiscadev/fakecloud` commit `4db815e2f225e06e592aec96c14ff85ec19cc0ba` (the `main` tip on 2026-09-28).

**Caveats that shape how a test uses these:**

- **The `test*` root bypass.** Any access key starting with `test` skips both SigV4 verification *and* IAM enforcement. The `dynamodb:Attributes` negative test (serving role tries `SET role = …` and must be denied) and any presigned-URL check must sign with a non-`test` key. Mint one with IAM `CreateUser` + `CreateAccessKey` and attach the role's policy, or `AssumeRole` into the serving role. Otherwise the test passes vacuously.
- **Safe-fail direction.** fakecloud evaluates an unextracted condition key to `false`, so the statement does not apply ([IAM evaluator](../../library/sections/web--fakecloud-reference-security--iam-evaluator-and-condition-keys.md)). For minion.town's ceiling, that matters in one direction. If the serving role's `UpdateItem` Allow is conditioned `ForAllValues:StringEquals dynamodb:Attributes [pk, credits]`, a key that fakecloud failed to extract would *deny* (safe). If the ceiling is instead expressed as a `Deny` on other attributes, a missed extraction would silently *allow*. The negative test exercises the real shape either way.
- **Enforcement coverage is partial.** Under `--iam strict`, only IAM, STS, SQS, SNS, S3, KMS, DynamoDB, and DynamoDB Streams are policy-checked. Cognito, Secrets Manager, and SSM are not, so fakecloud cannot rehearse the deploy role's Secrets Manager or SSM permissions ([IAM evaluator](../../library/sections/web--fakecloud-reference-security--iam-evaluator-and-condition-keys.md)).

## 2. The SDK license question (deferred in the parent note)

- **Facts.** The `fakecloud` npm package (`npm install fakecloud`, v0.46.0 at retrieval) declares `"license": "AGPL-3.0-or-later"`. `sdks/typescript/LICENSE` is the GNU AGPL v3 text, the same license as the repository root, with no permissive carve-out for the SDK. The package has **no runtime dependencies**; it is a `fetch` client ([TypeScript SDK](../../library/sections/web--fakecloud-sdks-typescript--typescript-client-surface-and-license.md)).
- **Reading.** As a devDependency in a test suite that minion.town does not distribute, AGPL obligations are unlikely to be triggered in practice. The AGPL's network clause concerns users interacting with a modified *program* over a network, and a CI test helper is not served to users. Still, adding an AGPL package to `package.json` puts it in the dependency graph that license scanners and downstream consumers of the repo see. The SDK's value for this project is small: the endpoints minion.town needs are `POST /_reset` (or `/_fakecloud/reset/dynamodb`), `GET /_fakecloud/health`, and possibly `GET /_fakecloud/cognito/confirmation-codes/{pool}/{user}` and `/_fakecloud/cognito/pretokengen/invocations`. Each is a one-line `fetch`.
- **Recommendation.** **Do not add the `fakecloud` npm package.** Have the DynamoDB/Cognito CI tier call the documented HTTP endpoints directly from a small local helper. Running the fakecloud *server* as an external container in CI is unaffected by this choice, as the parent note already said. This is a scholar's reading, not legal advice. If the maintainer wants the SDK for its typed Cognito helpers, that is a maintainer call.

## 3. Correction to the parent note

Parent §3 step 4 says to `POST /_fakecloud/reset` between tests. The introspection reference lists **no** whole-server `/_fakecloud/reset` route, only `POST /_fakecloud/reset/{service}` and `.../{service}/{account_id}`. The TypeScript SDK's `reset()` posts to **`POST /_reset`** (`sdks/typescript/src/client.ts` at `4db815e2`) ([introspection catalog](../../library/sections/web--fakecloud-reference-introspection--endpoint-catalog.md)). The build job should use `POST /_fakecloud/reset/dynamodb` (scoped, documented) or `POST /_reset` (global, SDK-used, not in the reference table).

## 4. Net effect on the parent recommendation

- **DynamoDB CI tier (`build-minion-town-fakecloud-dynamodb-tier`): strengthened.** The one thing the parent flagged to "verify in the build job", real `CancellationReasons`, is now known to match AWS's per-index shape. The duplicate-credit test can assert `CancellationReasons[0].Code === "ConditionalCheckFailed"` and `[1].Code === "None"` against observed behavior. Add an optional **fourth** case under `FAKECLOUD_IAM=strict` with a non-`test` key: the attribute-scoped serving policy must deny `SET role = …` and allow `ADD credits :c`. This would be the first executable check of the "admin ceiling survives billing" invariant outside real AWS.
- **Cognito CI tier: unchanged, slightly clarified.** Cognito calls are not IAM-enforced, so the tier tests token shape and triggers, not the deploy role's Cognito permissions. `mintAuthorizationCode` / `POST /_fakecloud/cognito/authorization-codes` offers a scripted path to an `authorization_code` token without driving `/oauth2/authorize` ([Cognito](../../library/sections/web--fakecloud-services-cognito--auth-flows-oauth-endpoints-and-introspection.md)).
- **Deploy rehearsal: still not recommended, now for a confirmed reason.** SSM Run Command does not run the script, so `deploy/aws/scripts/*` → `ssm send-command` → box cannot be rehearsed. At most, the control-plane half (S3 upload + presign, Secrets Manager create-if-absent) could run, with the presigned GET meaningful only under `--verify-sigv4` and a non-`test` key.
- **Still unverified:** presigned-URL expiry enforcement. It is not needed for any recommended job.
