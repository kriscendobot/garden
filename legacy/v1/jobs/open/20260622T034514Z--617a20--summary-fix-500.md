## Summary-fix bundle for endo-but-for-bots PR #500

Three summary-fix items from the barrister first-round code panel. The fixer addresses these in a single dispatch; no panel re-run required.

### Item 1 — retainUntil silently ignored when resultName is also set

In `packages/daemon/src/host.js` (and `guest.js`), when `resultName !== undefined`, the function returns `value` directly and never passes `retainUntil` to `retainUnnamed`. The caller receives no error or warning. Add a comment at the early-return branch noting that `retainUntil` is a no-op when `resultName` is set (or add a guard that throws for the combination if that is the intended contract).

### Item 2 — Pre-settled and pre-rejected retainUntil cases not tested

`packages/daemon/test/endo.test.js` covers the normal async-settle case for `retainUntil` (line 972-1006) but not:
- Already-resolved promise passed as `retainUntil` — confirm pin releases on next microtask and value is still returned.
- Already-rejected promise passed as `retainUntil` — confirm pin releases on rejection and value is still returned.

Add two tests covering these boundary cases.

### Item 3 — Guest-path retainUntil not tested

`packages/daemon/src/guest.js` also calls `makeRetainUnnamed(unpinTransient)` and threads `retainUntil` through the `evaluate` function, but no test exercises the guest path with `retainUntil`. Add a smoke test via the guest interface confirming the same retention behavior.
