## Ask 1: consolidate the 14 cycle-rename-tdz parity test files

The SCENARIOS table sits in `_cycle-rename-tdz-assertions.js` and carries one row per cell with these fields:

- `name`: short scenario identifier used in test titles.
- `fixture`: the fixture directory name under `packages/compartment-mapper/test/`.
- `reexportForm`: `star` or `named`.
- `binding`: `const`, `let`, or `var`.
- `order`: `renamer-first` or `star-first`.
- `expectedProbe`: the matrix's expected observation (an error envelope or a value envelope).

Both consolidated test files iterate the table with `for (const scenario of SCENARIOS)`. The SES side wraps `scaffold(scenario.name, test, fixture, assertFixture, 1)`; the Node.js parity side registers one `test(\`cycle-rename-tdz ${scenario.name} - node parity\`, ...)` per scenario that imports the fixture and asserts the same expected probe. Per-scenario parity is verified by construction: both layers consult `scenario.expectedProbe` from the same module so they cannot disagree.

The seven scenarios are: `star const renamer-first`, `star let renamer-first`, `star var renamer-first`, `star const star-first`, `star let star-first`, `star var star-first`, `named const renamer-first`.

Inline-thread reply (in_reply_to 3407540460): https://github.com/endojs/endo-but-for-bots/pull/379#discussion_r3407562677. Cites the addressing commit and the consolidation pattern.
