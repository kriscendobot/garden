# result: fixer — #411 Playwright pin 1.49.1 → 1.58.2 to escape single-mirror CDN failure

## Failing-log diagnosis

Pulled `gh run view 26912459352 --repo endojs/endo --log-failed`.
The `Install Playwright Browsers` step ran `npx playwright install
--with-deps` under a 3-attempt retry with 15-minute per-attempt
ceiling. All three attempts hung on the same single URL:

```
Downloading Chromium 131.0.6778.33 (playwright build v1148) from
https://playwright.azureedge.net/builds/chromium/1148/chromium-linux.zip
```

Each attempt timed out at exactly 900000ms (15m) without progressing
the download to completion. The cache step recorded `Cache not found
for input keys: playwright-Linux-<hash>` (cache miss on the new
lockfile hash, expected on the first run of a new branch).

So: cold cache forced a real download, the download hung on a single
CDN host, and the retry wrapper reissued requests against the same
host that was already failing. No retry of the same URL would have
helped.

## Root cause

Playwright 1.49.x downloads browsers from `playwright.azureedge.net`
as a single host. Reading `microsoft/playwright`'s
`packages/playwright-core/src/server/registry/index.ts` shows that
1.51 and later route through three CDN mirrors with failover:

1. `https://cdn.playwright.dev/dbazure/download/playwright` (ESRP CDN)
2. `https://playwright.download.prss.microsoft.com/dbazure/download/playwright` (Direct ESRP)
3. `https://cdn.playwright.dev` (Storage Bucket)

The 1.49 single-mirror model has no escape from a misbehaving host;
the multi-mirror model in 1.51+ routes around it. This is a structural
fix to the failure mode, not a CDN-seed-time issue (1.49.1 is from
December 2024, 17 months old as of today, plenty seeded already).

## Decision: pin to 1.58.2

Pinned `browser-test/package.json` `@playwright/test` from `^1.49.1`
to exact-pin `1.58.2`. Ran `npm install --package-lock-only` to
regenerate `browser-test/package-lock.json`.

Why 1.58.2 specifically:

- **Has multi-mirror failover** (post-1.51 registry).
- **Settled patch release** (1.58.2 is the last patch of the 1.58
  line, February 2025).
- **Well past CDN-seed window** (Feb 2025 release, 16 months ago).
- **Not the latest** (1.60.0 from May 2025): a settled mid-life
  release is safer than the newest for a "make CI green" pin.

Exact pin (no caret) keeps the lockfile cache key stable, so cold-cache
installs are one-per-branch and warm-cache installs are no-ops.

## Judgment calls

- **1.58.2 vs newer 1.60.0**: chose 1.58.2 over the latest stable
  1.60.0 for "settled" reasons. 1.60.0 is May 2025, still in its
  X.0.0 lineage with no patch; 1.58.2 is the .2 of an older line,
  so any post-release CDN or behavior issues will already have
  surfaced. Reasonable to revisit later if a maintainer prefers
  "track latest."
- **No retry-config bump**: kept the 3-attempt × 15m × 60m-job
  envelope from the prior fixer commit. With multi-mirror failover
  inside Playwright itself, the download path now has internal
  redundancy that did not exist before; the workflow-level retry
  becomes pure belt-and-suspenders rather than the primary recovery
  mechanism.
- **No cache-key change**: the existing key keys on
  `hashFiles('browser-test/package-lock.json')`, which moves
  automatically with the version bump. No workflow edit needed.
- **Not authorized to touch endo upstream**: did not edit
  `endojs/endo` directly; the boatman will ferry this commit as
  part of the next re-ferry of #411 → endo#3296.
- **Skipped `npm install --ignore-scripts`**: used
  `--package-lock-only` to update only the lockfile (no
  postinstall scripts run, no browsers downloaded locally). The
  `.npmrc` in `browser-test/` already sets `ignore-scripts=true`,
  so this is defense in depth.
