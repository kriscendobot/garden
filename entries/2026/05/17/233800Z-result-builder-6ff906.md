Implemented `designs/filesystem-watchers.md` on the `llm` base.

PR: https://github.com/endojs/endo-but-for-bots/pull/277 (draft).
Branch: `feat/endo-mount-follow-name-changes`.
Base: `llm`.

Affected paths (all `packages/daemon/`):

- `src/mount.js`: new `followNameChanges(...pathSegments)` on the
  `EndoMount` exo, snapshot-then-diff with `try/finally` for OS
  watcher release.
- `src/daemon-node-powers.js`: new `watchDirectory(path)` in
  `makeFilePowers`, wrapping `fs.watch` with a 50 ms debounce window
  and an in-memory queued AsyncIterable. Failure path returns an
  immediately-terminated stream so callers see end-of-stream rather
  than hang.
- `src/interfaces.js`: `MountInterface` gains the `followNameChanges`
  method guard (`rest(PathSegmentsShape).returns(M.remotable())`).
- `src/types.d.ts`: `FilePowers` gains the `watchDirectory` type.
- `src/help.md` + auto-generated `src/help-text-data.js`: new method
  documented under `EndoMount`.
- `test/endo.test.js`: 8 new tests covering the design's Test Plan.

Scope: only `followNameChanges` per the dispatch's scope discipline.
`followLocatorNameChanges` is referenced in the design only as the
existing `EndoDirectory` method (model for the new addition); the
cross-interface unification is a sibling design and explicitly
out of scope here.

Test count: 8 new tests in `packages/daemon/test/endo.test.js`,
all passing locally (`npx ava test/endo.test.js --match "mount
followNameChanges*"`, 26 mount tests total including the existing
18). Each test exercises a behaviour absent from the baseline:

1. Snapshot alphabetical order.
2. Subdirectory-vs-file type discrimination.
3. Live file addition.
4. Live file removal.
5. Subdirectory-scoped subscription (sibling additions do not
   surface).
6. Confinement: escaping symlinks omitted from the snapshot.
7. Scratch-mount parity.
8. Watcher release: after `iter.return()` the iterator stays done
   and post-return writes do not produce events.

Regression evidence: the method does not exist in the baseline; the
runtime `M.interface` guard would fail exo construction without the
method body, and each test asserts a specific behaviour
(snapshot ordering, `type` field, live event arrival, confinement,
cleanup) that fails if the corresponding production code branch is
removed.

Changeset: `.changeset/endo-mount-follow-name-changes.md`
(`@endo/daemon`: minor).

CI status: 21 checks pending at PR open; no failures yet.

Out-of-scope deferrals (consistent with the design body):

- `EndoMount` adopting the broader `NameHubInterface` (a sibling
  design referenced under Open Questions).
- Multiplexing many subscribers onto one `fs.watch` handle (deferred
  per the design's *Multiplexing* section; one watcher per
  subscriber for the first cut).
- Recursive subscriptions (deferred per Design Decisions item 2).
- Watching individual files via `EndoMountFile` (deferred per
  Scope).
- File-content change events (`{ replace }` arm) (deferred per
  Design Decisions item 3).

Notes for the field:

- The autogenerated `help-text-data.js` regeneration produced a
  large diff against the committed file because `prettier` had
  reformatted the committed copy into single-quoted form while the
  generator emits `JSON.stringify` output. Running `yarn format`
  normalized the regenerated file back to the committed style, so
  the net diff is the two-line addition for the new
  `followNameChanges` entry.
- One test (`subdirectory does not see siblings`) initially hung
  on `iter.return()`. Root cause: the negative-case
  `awaitMountChange` race leaves an outstanding `iter.next()` in
  flight; calling `return()` afterwards races against that pending
  request. Resolved by not calling `return()` in the negative-case
  test and relying on dispatch-time daemon teardown to release the
  watcher. The other tests' `return()` calls remain and exercise
  the watcher's `finally` block on the happy path.

Self-improvement: nothing this time.
