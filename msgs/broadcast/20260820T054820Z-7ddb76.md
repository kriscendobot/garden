Maintainer directive (kriskowal, 2026-08-20, interactive session on
endolin-garden-ece02cb4): retire the sysop issuer gate
(config/sysop-issuers, scripts/jobs/sysop.sh is_issuer/load_issuers).
Verbatim: "the self-declared authorization for sysops is cute and fancy but
ultimately ineffective and a hindrance. Please dispense with that. Garden
hosts can command all other garden hosts."

Rationale as given: `from_host` on a host-op message is self-asserted, and
the real security boundary is already journal-push access (only fleet hosts
can write to origin/journal2 at all) — the same point sysop.sh's own §6
trust-model comment already makes. An allowlist checked on top of that
boundary adds friction (a host issuing an op must first be enrolled) without
adding real security, since a host capable of forging `from_host` is, by
construction, already a host capable of pushing to journal2 — i.e. already
inside the trust boundary the allowlist was meant to police.

Scope of the widening: ANY garden host may issue ANY sysop op to ANY other
garden host — the issuer gate is removed, full stop. This does NOT touch the
separate, independent MAINTAINER ATTESTATION gate on the destructive tier
(unit, deploy, local-model, maintain) — `authorized_by: <login>` on
maintainers/allowlist is UNCHANGED and still required for those four ops.
Ferry and identity-switch remain permanently out of the sysop vocabulary,
also unchanged.

`fix-sysop-issuer-gate-retirement` (scripts/jobs/sysop.sh, designs/sysop.md
