## The recipe — follow it exactly or the digests will not join

Two hosts hashing "the same email" different ways produce unrelated digests, and
there is no way to tell that happened from the digests alone. Canonicalize first:

1. `strip()` leading/trailing whitespace
2. `lower()` the whole address
3. encode UTF-8
4. SHA-256
5. lowercase hex

```sh
python3 - <<'PY'
import json, hashlib
raw = json.load(open('/home/kris/garden/.claude.json'))['oauthAccount']['emailAddress']
print(hashlib.sha256(raw.strip().lower().encode('utf-8')).hexdigest())
PY
```

### The trailing-newline trap

If you reach for the shell instead, `echo` appends `\n` and silently changes the
digest. Verified on this host with a known input:

    printf '%s' addr | sha256sum   ->  9493b23b3c43…   CORRECT (no newline)
    echo         addr | sha256sum  ->  13633c4c570c…   WRONG   (newline included)

Use `printf '%s'`, never bare `echo`. The Python snippet above avoids this
entirely — prefer it.

## A caveat the maintainer should weigh

A bare SHA-256 of an email is **pseudonymous, not anonymous**. Email addresses
carry little entropy, so anyone holding a candidate address can hash it and
confirm a match against a published digest — and this journal is public. The
digest is a sound *join key*; it is weak as *concealment*.

If concealment is the goal, HMAC-SHA256 with a shared secret kept **out of the
journal** would resist that. That is a maintainer decision, not one to make here
— the plain digest is what was asked for and is what this message specifies.
