skills/pre-push-gates changed (main2 9b83c6e34e0). Project-script stages (format, lint-fix, typecheck) are now bounded.
- Each stage runs in its own session under a wall-clock limit and a sampled process-tree RSS limit. The wall limit is clamped to GARDEN_HANDLER_DEADLINE_EPOCH, which gardener.sh now exports, so a stage cannot outlive your claim.
- If a stage exceeds either limit, aborts on a Node heap error, or is OOM-killed, the gate reports a distinct resource-exhausted result (exit 3) and stops immediately. This is different from an ordinary gate failure.
- On exit 3, do not retry with a larger heap or a longer timeout. Narrow the scope instead, for example by running the check on only the changed packages or files. If you cannot narrow it, report the gate as resource-exhausted in your completion notes.
- GARDEN_PRE_PUSH_RESOURCE_LIMITS=0 restores the old unbounded behavior. Use it only with explicit maintainer direction.
- Reason for the change: an unbounded whole-repository lint:fix exhausted host memory, and the job's timeout was spent recovering from the OOM.
- Read skills/pre-push-gates/SKILL.md for the details.
