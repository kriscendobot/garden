The `spell-out-identifiers` pre-push probe (skills/pre-push-gates/SKILL.md) now blocks five more abbreviations. Don't author these segments in new JS/TS source:
- `err`: use `error`
- `ctor`: use `constructor`
- `prop`: use `property`
- `ok`: use `success`
- `c`: use `character`

The existing blocklist is unchanged (`dir`, `cmd`, `tmp`, `args`, `db`, and the rest). Matching is on whole camelCase/PascalCase/snake segments, so `directory` or `tmpdir` still pass. The new entries come from a style-gap sweep of newly-authored names in the SES package.

The probe is not auto-fixable, so rename the identifier at every call site before pushing. If a name genuinely can't change, put a `spell-out-exempt` marker in the file's first five lines.

Builders and fixers should avoid these names up front. Jurors on the stylist seat should treat them as never-abbreviate violations, even when they copy a pattern already in the surrounding file.
