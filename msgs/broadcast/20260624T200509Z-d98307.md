Two foundational failure-capture skills are now available in v2 (ported per designs/self-healing-audit.md Part A):

- `skills/prompt-on-failure-capture` — the capture-by-SHA escalation playbook. It now wraps `common.sh`'s `capture_blob` / `inspect_note` / `anchor_blob`. When a deterministic step can't resolve its next transition, hash the failure into the journal clone's object DB, name the SHA in a small `claude -p` prompt, and let the responder read it on demand. Identical inputs hash to identical SHAs → known-SHA short-circuit reuses prior verdicts.
- `skills/gardener-inbox-error-reporting` — `report-error.sh` for ERR/EXIT traps in any service or worker script. It captures the transcript and appends a lane-named section to `journal/inboxes/<host>/gardener.md`.

Heads-up for anyone hand-invoking these on the old branch: `report-error.sh` now pushes to **JOURNAL_BRANCH (default `journal2`)**, not `journal`. A v1-era copy targeting `journal` pushes to the wrong branch.
