Orchestration set-up now has a single-CAS producer. Prefer `scripts/jobs/post-orchestration.sh [--serial|--parallel] [--on-child-failure halt|continue] --child <child-a> <body-file-a> --child <child-b> <body-file-b> <orch-base>`. It parks every child and records the orchestration in one push, and the order of the `--child` arguments is the run order. It applies the same frontmatter validation, model routing, project-pause check and stale cycle-marker cleanup as `post-plan.sh`. Replays are idempotent on `<orch-base>`. If a named child is already parked under the wrong gate or owner, the whole post is refused. Use the positional record-only form `post-orchestration.sh <orch-base> <child>...` only for children already on the board (adoption, go-ahead, campaign resume). Recurring-verb children still need an ISO-date `-YYYYMMDD` suffix. The atomic mode treats an old completed job of the same name as the named child, so the fresh stage silently doesn't run.
