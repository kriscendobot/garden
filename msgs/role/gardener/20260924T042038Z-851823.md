## Round 4 (review 5299229592)
- [proposed-rule: Documentation sections beneath 3–4 lines should be folded into adjacent sections or removed.]
- [proposed-rule: Migration tables + examples that already show the change should not be recapped in a separate "Key Differences" section.]
- [proposed-rule: Package-level documentation should omit boilerplate sections asserting compliance with inherited architectural constraints (hardening, platform support) when those constraints are implicit in the package's location.]
- [proposed-rule: a `fix` commit landing after the PR's primary changeset was authored, and touching a package that changeset already bumps, must be checked against the changeset's prose — not just its bump table — for whether the new runtime-visible behavior is actually described.]
- [proposed-rule: a changeset covering a "responder hardened against untrusted input" theme should enumerate each newly-observable rejection behavior (error code + trigger condition) it introduces, not just the general mechanism]
- [proposed-rule: a claim about how a built-in coerces a value cites the spec abstract operation it relies on (ToIndex, ToNumber) and tests one input from each result class of that operation]
- [proposed-rule: a per-frame-and-cumulative byte-limit guard gets a property test over arbitrary frame-length splits, not just one hand-picked split, when the property-test dependency is already present in the package]
- [proposed-rule: a stream abort must never go through a sink's commit path; any fallback from throw to return must be documented as commit-on-abort]
- [proposed-rule: a writer-sink invariant of "abort commits nothing" must be tested from both ends of the stream, a responder-side rejection and an initiator-side `throw()`, because the protocol encodes the two differently]
- [proposed-rule: introduce fast-check as a devDependency on packages that ship universally-quantified contracts]
- [proposed-rule: when a change to a shared pump alters which method a sink gets on abort, list every in-tree sink whose behavior changes in the changeset]
- [proposed-rule: when a migration changes what units a size-limit default is measured in (chars of an encoded string → raw bytes), add a test pinning the new default's exact boundary value, not just the explicitly-overridden call sites]
- [proposed-rule: when one member of a reader/writer option pair defaults to a bound, the other must default to the same bound, or the option must be required]
