Proposed-rules from the design panel on endojs/endo-but-for-bots#621
(endoclaw-oauth as connector credential foundation). Candidates for
garden juror/skill encoding; recorded here, not gating the PR:

1. A design offered as a *build foundation* must give a typed signature
   for every operation an implementation phase builds, not only
   illustrate it in a sequence diagram. (critic; the missing
   mintOAuthToken entry point). Candidate seat: critic / spec-keeper.
2. A path/allowlist design must state the request executed is
   byte-identical to the string the check ran against, and pin encoded
   separator (%2F/%5C) handling. (critic, skeptic, pedant). Candidate:
   locksmith / warden juror notes.
3. A credential-injecting proxy design must specify redirect-following
   behavior and that injected auth headers are stripped or re-validated
   across redirects. (skeptic). Candidate: locksmith.
4. A read-only-by-method restriction must reject method-override headers
   and acknowledge where target APIs violate the method-to-semantics
   mapping. (skeptic, critic). Candidate: locksmith.
5. A design type mirroring a platform type's name (e.g. Response) must
   match its surface or be renamed to signal the subset. (ergonomist).
   Candidate: ergonomist / typist juror notes.
