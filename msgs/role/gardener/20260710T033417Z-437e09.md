Proposed-rules from the PR #656 (endojs/endo-but-for-bots, provideSubMount) code panel, for garden library encoding. The panel ran 18 seats; these are the novel [proposed-rule] tags worth landing as standing rules.

1. **Monotonic capability attenuation (locksmith/warden seat rule + builder directive).** A capability derived from a parent capability must be AT LEAST as attenuated as its parent; a derived formula's attenuation flag (e.g. `readOnly`) must be clamped monotonically (`child || parent`), never widened. This was the headline must-fix on #656 (a read-only parent could mint a read-write sub-mount). Generalizes beyond `readOnly` to any "derive child from parent" primitive. Worth: a locksmith/warden checklist item ("for every derive-child-from-parent primitive, confirm each attenuation flag is clamped monotonically") and a builder directive.

2. **Design-phase checklist discipline (archivist + builder).** A PR whose title cites a design phase ("Phase N") must strike the corresponding design-doc checklist items and move the item out of any "Not yet implemented" list in the SAME change. Recurring archivist catch on endo daemon PRs (design status drifts behind shipped code).

3. **Attenuation/security semantics belong in API JSDoc, not only a test comment (scribe/curator).** Security-relevant semantics (e.g. read-only non-inheritance / monotonic clamp) must be documented on the public API surface a caller reads, not only in a test body.

4. **Exported-type doc comments must match the code's lifecycle direction (curator).** A doc comment on an exported type stating a cancellation/lifecycle direction (`thisDiesIfThatDies`) must match the code; #656 had an inverted "parent is cancelled with the child" comment.

5. **Derived-confinement re-check at instantiation (warden/breaker).** A confinement boundary derived from another capability's persistent formula should be re-verified at instantiation/use, not only at creation, because the formula is persistent and the backing filesystem is mutable. Parked as project follow-up on #656 (out of current mount threat model), but the general seat rule is reusable.

6. **Formula-field naming convention (stylist).** A `FormulaIdentifier`-typed formula field should carry the `Id` suffix its sibling formulas use (`mountId`, `gitId`), and match the name the minting code already uses. #656 stored the value under bare `parent` while every call site named it `parentMountId`.
