## Proposed rules (deduplicated)

- [proposed-rule: A stream/queue producer that pre-acknowledges ahead of consumer demand must state, and a test must pin, the maximum data delivered after a revocation/cancellation signal — "next pull rejects" is not equivalent to "no more data arrives" once a pre-ack buffer is nonzero.]
- [proposed-rule: a PR that adds an option-gated code path (`sorted: false`) to a shared engine function should not change the unconditional-cost profile of the existing default path; diff the before/after cost of the *default* option value, not just the new one.]
- [proposed-rule: a PR that removes an eager result/byte cap on a capability method must state, in the same PR, who newly gains unbounded access versus who already had multi-call access to the same data.]
- [proposed-rule: a changeset body's markdown puts one sentence per line so review diffs and per-sentence edits stay legible]
- [proposed-rule: a changeset describing a new option states the option's actual lifetime, not the weaker guarantee the implementation was aiming at]
- [proposed-rule: a changeset must be internally consistent with the head's behavior, not an accretion of superseded commits]
- [proposed-rule: a comment asserting "X is the bound" names the dimension it bounds when an adjacent dimension is unbounded]
- [proposed-rule: a cross-file "see X" code comment citing a sibling mirror site should be checked for staleness whenever the cited sibling changes]
- [proposed-rule: a defensive guard added in a diff must either be reddened by a test or deleted with its claim]
- [proposed-rule: a design doc's Status flip to "Implemented" is reviewed against the merged diff's actual file/function names, not just its high-level claims]
- [proposed-rule: a doc comment stating a capability's revocation/atomicity guarantee must be updated whenever a new method weakens that guarantee for any subset of calls, even if the exception is documented elsewhere.]
- [proposed-rule: a generated model-facing declaration must not degrade a mandatory parameter to `unknown` when its type is already declared in the same artifact]
- [proposed-rule: a generated model-facing declaration must not emit `unknown` for a parameter whose type the same file already declares]
- [proposed-rule: a help-text usage example must be independently copy-pasteable - every identifier it references must be bound within the example itself.]
- [proposed-rule: a limit opt-out must be justified separately for each direction it is applied; an output-parity argument does not license an input guard]
- [proposed-rule: a method's `types.d.ts` JSDoc must state the same behavioral caveats (eagerness, incrementality, ordering) that the implementation comment and generated help text state for it — the three surfaces are the method's whole public contract and must not diverge.]
- [proposed-rule: a method's public JSDoc/help-text performance claim must not contradict that method's own implementation comment in the same PR — cross-check the two before landing.]
- [proposed-rule: a minor-versioned public option must have a non-test caller in the same PR, or the changeset must state it is substrate-only]
- [proposed-rule: a new field on a published `*Options` type must be added to the README's option list for every function that accepts it]
- [proposed-rule: a new option that opts out of a normative cross-language ordering must document the replacement order as unspecified, or specify it.]
- [proposed-rule: a new public option added for a follow-up must be named as unused-substrate in the changeset, or split out of the PR that does not consume it]
- [proposed-rule: a new public option on a shared engine lands with a production caller or not at all]
- [proposed-rule: a new public option shipped in a release changeset has an in-repo consumer, or the changeset names it as substrate-only]
- [proposed-rule: a revocation-completeness claim must name the multiplicity it is quantified over.]
- [proposed-rule: a streaming-reader design that documents a per-reader resource bound as closing a "k*x" multiplier must also state whether the bound holds across multiple readers minted by the same grantee, not just multiple streams on one reader]
- [proposed-rule: a test assertion may not be gated on a fixed wall-clock deadline shorter than its own `t.timeout`; wait for quiescence, then assert]
- [proposed-rule: a wrapper that returns an iterable/view is named for the value it produces, not for the side effect it performs during later iteration]
- [proposed-rule: an equivalence between two modes of one engine is tested by sweeping the existing normative case table through both, never by a hand-picked subset]
- [proposed-rule: an opt-out of a pattern resource limit is justified per *direction*; an inbound guard on caller-supplied data may not be laxer than the eager surface's equivalent guard.]
- [proposed-rule: an option's JSDoc must state the latch's lifetime when the implementation never resets it.]
- [proposed-rule: any exception to the "revoke() is an atomic cutoff for every derived face" invariant must be called out by name in the `EndoMountControl.revoke()` JSDoc block itself, not only in the per-method comment, since that block is the canonical statement of the invariant.]
- [proposed-rule: don't export a public option with no in-tree consumer; land it with the caller]
- [proposed-rule: flipping a design's Status to Implemented requires reconciling every normative claim in the doc against the landed code, not just adding new sections.]
- [proposed-rule: introduce fast-check where a package ships universally-quantified contracts]
- [proposed-rule: numbered decision/rationale lists in design docs keep monotonically increasing source numbers, even though rendered markdown re-numbers automatically — a future editor diffing raw source shouldn't have to guess where an item belongs]
- [proposed-rule: ordered-list labels in design docs must match render order, so a review citing "decision N" resolves identically in both.]
- [proposed-rule: panel-review provenance markers never survive into merged source; the reason a test exists is stated in its own terms]
- [proposed-rule: regenerating a generated artifact must not drop content the checked-in artifact carried; diff old-vs-new content, not just the added rows]
- [proposed-rule: streaming-authority-entry-points-need-a-real-escape-fixture]
- [proposed-rule: the judge's round-aggregation step should assert `count(proposed-rule tags this round) == count(gardener messages sent this round)` before submitting the review, failing loudly rather than relying on a later scribe pass to catch drift.]
- [proposed-rule: when a diff touches `test/generated/code-mode-globals/*`, the changeset-auditor should check whether prior changesets for the same generated-globals class named the package explicitly, and require the same here.]
