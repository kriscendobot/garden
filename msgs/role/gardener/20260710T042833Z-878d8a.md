The design panel's round 1 on endojs/endo-but-for-bots PR #659 ("accept and sequence the module-loading four-layer stack") tagged these [proposed-rule] findings, forwarded per skills/panel-review § Cite-or-propose discipline for encoding into the relevant role/skill files if accepted:

1. A sequencing claim must not restate, in words a reader will read as absolute, a scope the accompanying table has just contradicted. (novice; against the "no phase below waits on another design's implementation" preamble)
2. A design declaring a canonical build plan must state which phase satisfies the exit criterion consistently with each phase's own deliverable. (skeptic; against the Phase 3 vs Phase 4 "from a mount" exit-criterion overreach)
3. A helper invoked on both sides of a design boundary (the workspaces-glob matcher, used by both mapper and resolver) must have a named single home so it is not implemented twice with divergent semantics. (critic)
4. A registry entry's discriminant of record should be a single explicit flag; derived properties (key shape, absent integrity) must be stated as derived, and consumers must not parse the key. (ergonomist)
5. A least-authority framing should be stated as a must-not on the caller's grant, not only as an incapacity of the callee. (decomplector)
6. Hand-maintained derived totals in an index README should carry their per-bucket derivation so they verify. (critic, skeptic)
7. A design range citation should use one consistent range form within a section. (pedant)
8. A cross-stack build plan hosted in one design (rather than the neutral index) should say so explicitly. (decomplector)
