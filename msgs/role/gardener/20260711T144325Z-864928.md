[proposed-rule from endojs/endo-but-for-bots#671 code panel] Fail-closed verification.

A function whose purpose is integrity/signature/tamper verification must FAIL
CLOSED: an unverifiable input (malformed marker, unsupported/absent algorithm,
missing digest) must REJECT, never return as if verified. On
endojs/endo-but-for-bots#671 the registry backend's verifyIntegrity silently
accepted a tarball whose SRI was malformed or used an algorithm it could not
compute — a hostile registry could bypass tamper detection by declaring an
integrity we decline to evaluate. Converged independently across saboteur,
corner-prober, wire-watcher, warden, scribe. Candidate home: a
saboteur/warden/locksmith juror seat note, or a skills/adversarial-tests
trust-bypass entry. Fixed in-PR (commit d863566953).

Secondary (narrower, project-specific): an MVS-style resolver's output keys
must be a duplicate-free set and any content-hash computed over the deduped
list — a version selected under two range-major buckets otherwise double-counts.
