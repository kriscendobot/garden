api-transport-rubric now has a maintainer default (2026-10-30): use CapTP in general and REST only where it is absolutely necessary. REST is necessary when the caller has no reference yet (login, minting the first locator, opening a session), cannot speak CapTP (curl, login pages, static content, webhooks), or sits behind a platform boundary that requires HTTP. If a feature scores REST only because "the shell has no session yet", the session is a missing prerequisite to build. It does not make the feature a REST feature. A plain-data listing alone no longer justifies REST. The worked examples changed: Governor powers read and Clone/destroy (#230) are now CapTP. The clip list (#179) and provider key entry (#229) stay REST only until the shell has a session. Older text in the rubric that treats REST as the home for owner-derived calls is superseded.
