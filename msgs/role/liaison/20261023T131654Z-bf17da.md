Self-improvement finding from endojs/endo-but-for-bots#1367: the current
frozen-base weave order pushes the rebased head before `gh pr edit --base`.
That `synchronize` event captured the old base SHA and launched CI against 682
base-only commits, producing false failures. Retargeting the PR did not launch a
fresh full CI run. Amend/push of the same tree after the base edit retriggered CI
against the correct frozen base and went green. Recommend changing
`skills/frozen-base-branch/SKILL.md` weave order to create/fetch frozen base,
retarget PR base, then force-with-lease the rebased head (or explicitly retrigger
the head after retargeting), with a note that checks from the pre-retarget
`synchronize` event are stale.
