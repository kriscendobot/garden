Self-improvement (structural) from scholar-ingest-unum — a control-surface proposal for the maintainer to weigh deliberately.

## The gap
The garden meters token spend only at ONE granularity: `scripts/jobs/usage-meter.sh`
sums the fleet's billable tokens over a trailing weekly window (from Claude Code's
own `~/.claude/projects/**/*.jsonl` logs) so the foreman can back off before the
weekly Max-x20 quota. That is a fleet-wide QUOTA GATE, in plain code with no LLM —
good, and it should stay. But it is NOT an attributed ledger: it cannot answer
"which job / role / model spent the tokens," keeps no per-job persisted record,
and gives the maintainer no "where did the spend go" view. A completed job's
`tada/` report carries no cost block.

## The pattern (from jcorbin's `unum`, now in the library)
`unum` runs a fully-built complementary layer — a per-run ATTRIBUTED cost ledger.
Ingested this cycle as concept [[cost-ledger]] with worked sections
`library/sections/unum--token-cost-ledger.md` and `unum--cost-attribution-and-aggregation.md`:

- One JSON line per agent run, appended `O_APPEND` best-effort to a gitignored
  runtime file, capturing the four token classes + the CLI-computed `total_cost_usd`
  + wall-clock + host rusage (CPU/RSS), tagged with session / trigger / role /
  task / model.
- Read-time aggregation only: `invoke cost --by task|day|model` — a new axis is a
  new group key, not a schema change. Sorted by dollars descending.
- Three surfaces: an on-demand table, a per-task `## Cost` stanza baked into the
  completed-task archive (idempotent via an HTML-comment marker), and a live
  one-line operator chip.
- Stores the provider's dollars AND raw tokens (dollars now, tokens re-priceable).

## Why it maps cleanly onto the garden
Every gardener job is a `claude -p` run whose transcript already carries the same
`usage` block; the job base is a natural attribution key (unum's `task`). So the
building blocks exist. Candidate shape: a per-job cost record keyed by job base,
written on `doin -> tada`, aggregatable by job/role/model/day, optionally rendered
as a `## Cost` block on the `tada/` report or a bulletin line — and it could FEED
the existing usage-meter rather than replace it (ledger measures, gate caps).

This is a job-lifecycle + control-surface change (a new spend field / surface,
possibly a model-selection/budget evolution), so per the scholar's bounds I am
NOT editing roles/skills/docs — routing it here for the maintainer to act on
deliberately. Related library material: concepts [[model-routing]] (unum's
per-persona model tiers) and [[vigil-charge]] (a health-gated budget on PROACTIVE
agent spend — spend initiative tokens as a reward for verified stability, not just
when under quota; a possible refinement to the foreman's idle plan-pump).
