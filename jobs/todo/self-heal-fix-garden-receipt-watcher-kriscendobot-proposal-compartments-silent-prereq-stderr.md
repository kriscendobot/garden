In scripts/jobs/receipt-watcher.sh, the prerequisite die at line 91 ("receipt journal prerequisite failed for $repo (rc=$prereq_rc; see prerequisite stderr above)") fires unconditionally after `sed 's/^/  prerequisite: /' "$PREREQ_ERR" >&2` (line 89), even when $PREREQ_ERR is EMPTY — which is exactly what happened for kriscendobot-proposal-compartments at 02:04:08 (captured self-heal blob c69ad1bae5542b0c39a09d18c08f5b707a29a47e is a single FATAL line with zero preceding "prerequisite:" content). An empty PREREQ_ERR means the `( ensure_clone "$DIR"; sync_clone "$DIR" )` subshell at line 83 exited nonzero via bare `set -e` propagation from a command that failed without going through `log`/`die` (every logged failure path in ensure_clone/sync_clone/clone_lock in common.sh would have produced stderr text, which is absent here) — so the die message's "see prerequisite stderr above" is actively misleading when there is nothing above. Fix: guard the sed/die block on `[ -s "$PREREQ_ERR" ]` and emit a distinct message when the file is empty, e.g. "(no stderr captured — a command inside ensure_clone/sync_clone failed silently under set -e; rc=$prereq_rc)", so future incidents on this shared clone (also used by all 15 receipt-watcher@ template instances plus the same-shaped ci-watcher/comment-watcher verify clones) are diagnosable from the captured blob alone instead of dead-ending on a phantom "above".
