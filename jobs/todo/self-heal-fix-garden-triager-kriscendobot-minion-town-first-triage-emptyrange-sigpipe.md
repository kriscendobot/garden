Fix two compounding first-triage bugs in `scripts/jobs/handlers/triager-claude.sh` (line 27) that make the triage handler die under `set -euo pipefail` before it logs anything, whenever a repo's triager cursor is `<none>` (empty `old`). This makes `garden-triager@<slug>` crash-loop on first triage of any repo. Reproduced deterministically on `kriscendobot-minion.town` (cursor `<none>`, 811-line history): handler exits 128, then 141.

Bug 1 — empty-revision expansion (exit 128): line 27 uses `"${old:+$old..$new}"`, which expands to the EMPTY STRING when `old` is empty (the `$new` is trapped inside the `:+` alternate). `git log … ""` → `fatal: bad revision ''` → 128, propagated by `pipefail`. Fix: mirror line 26 — change the revision argument to `"${old:+$old..}$new"` so a first triage passes `$new` (full history to new) and an incremental triage passes `$old..$new`.

Bug 2 — `head -400` SIGPIPE under pipefail (exit 141): even after Bug 1, `git log … | head -400` on a history longer than 400 stat-lines makes `head` close the pipe early, git dies with SIGPIPE, and `set -o pipefail` propagates 141, killing the handler. Fix: replace `| head -400` with `| sed -n '1,400p'` (sed consumes the whole stream instead of closing early, so git exits 0 and the 400-line cap is preserved). Do NOT paper over it with a blanket `|| true`, which would also swallow genuine git failures.

After both edits, verify with: `bash scripts/jobs/handlers/triager-claude.sh kriscendobot-minion.town "" 35e9b4a53a7c7b29eb85dfe3e2397bc9fcbe9cfa repos/kriscendobot-minion.town.git </dev/null` exits 0 and logs `posted N job(s)`. Also confirm the incremental path (non-empty `old`) still produces `$old..$new`.
