The transient-connectivity signature list has drifted between two places. `_fetch_stderr_is_offline()` in `scripts/jobs/common.sh` matches `Could not resolve hostname`, `Temporary failure in name resolution`, `Could not read from remote repository`, AND `Connection timed out`. The belt-and-suspenders fallback grep in `scripts/jobs/self-heal-run.sh` matches only the first three — it is MISSING `Connection timed out`. A raw-git path (outside `journal_fetch`) that dies on a "Connection timed out" outage will therefore be misdiagnosed by self-heal as a real failure and burn a responder, instead of being normalized to a clean exit. Fix: make self-heal-run.sh's fallback grep use the same canonical signature set as `_fetch_stderr_is_offline()` — either by adding `Connection timed out` (and `Temporary failure in name resolution`, already present) to the grep alternation, or better, factor the signature list into one shared definition in `common.sh` (e.g. a `GARDEN_OFFLINE_SIGNATURES` regex constant) that both the function and the self-heal grep consume, so the two lists can never drift again.
