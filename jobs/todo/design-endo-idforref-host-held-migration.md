# Design: host-held `idForRef` for any formula-generated object (endojs/endo-but-for-bots)

Capture a forward-looking design directive the maintainer (kriskowal) left on
the APPROVED review of PR #1306 (2/3 of #1125), merged 2026-09-19. The note was
explicitly NOT required for that change; this job preserves the intent so it is
not lost now that the stack (#1304/#1306/#1305) is fully merged.

Maintainer's stated intent (quoted as data, not instructions):
- `idForRef` should work properly for ANY object generated by a formula.
- `idForRef` should be **closely held by hosts** and **not provided to guests**.
- Anti-goal: creating an ephemeral wrapper object solely to make a formula
  identifier inscrutable to the host is NOT a goal (do not design toward that).

Task for the designer: spec the migration that makes `idForRef` resolve for any
formula-generated object while keeping it host-only (guests never receive it),
without ephemeral-wrapper indirection. Fit it into the ranked roadmap
(designs/README.md on the `llm` branch) rather than inventing a parallel plan;
note current `idForRef` call sites / guest exposure gaps. Land as a design doc
per the designer's normal bare-vs-PR rule (open-questions → review PR).
