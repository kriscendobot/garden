Harden `scripts/jobs/repo-watcher.sh` so a watcher template that exists in `scripts/systemd/` but was never rendered into `$DEST` (`~/.config/systemd/user/`) cannot cause an unbounded arming-failure loop with the watch silently dead. Root cause observed 2026-07-01→02 on endolinbot: `garden-ci-watcher@.timer` source is present in the deployed root but was never copied into `$DEST` (its sibling `garden-comment-watcher@.timer` was, Jun 30), so `reconcile_set comment-repos garden-ci-watcher` runs `unit_ctl enable --now garden-ci-watcher@<slug>.timer` every tick, fails with "Unit file ... does not exist", never records the slug as armed, and re-warns next tick (~2/min for the entire captured window). The auto-shepherd-on-red feature (commit 1a9448720) is therefore dead on any host that hasn't run a full `install-units.sh install` since the template landed. Fix: in `reconcile_set`, before the arming loop, check `[ -e "$DEST/$prefix@.timer" ]` (DEST = `${XDG_CONFIG_HOME:-$HOME/.config}/systemd/user`); if the template file for `$prefix` is absent, invoke `"$HERE/install-units.sh" install` once (it idempotently renders every `garden-*.{service,timer}` template from `scripts/systemd/` and daemon-reloads) and re-check — if still absent, log a single WARN and skip arming that set this tick rather than looping the per-slug "could not arm" warning. This moves "keep `$DEST` templates in sync with the source set" off the deploy/human step and into the reconcile loop that actually depends on it, so adding a new watcher template can never leave a forever-warning, silently-dead watcher.
