scripts/jobs/install-units.sh
The `scale`, `reconcile_identity`, and `enable_services` paths mutate unit state with blocking `enable --now` / `disable --now` / `restart` calls wrapped in `unit_ctl_bounded` (5s `GARDEN_UNIT_CTL_TIMEOUT`, `timeout -k 2`). Observed in the journalctl tail: 136 of these exceeded 5s and were SIGKILLed in a single 20‑minute window (65 `disable --now`, 52 `enable --now`, 19 `restart`), because `--now`/`restart` block until the start/stop job finishes and, over a ~100‑unit pool on one busy `--user` manager, that reliably takes >5s. The bound then just kills each call, the pool never converges, and every scaler tick re‑issues the same doomed calls. Fix: stop blocking on job completion. Split the fast, synchronous file operation from the slow job: use `unit_ctl enable "$u"` (persistent, cheap) followed by `unit_ctl_bounded start --no-block "$u"`, and `unit_ctl disable "$u"` followed by `unit_ctl_bounded stop --no-block "$u"`, and `restart --no-block` in `reconcile_identity`. `--no-block` returns as soon as the job is enqueued rather than waiting for the gardener's `claude -p` to drain, so each call finishes well under the bound and the SIGKILL storm ends; the scaler's existing "a later tick observes convergence" model already tolerates asynchronous completion, and the `gardener_busy` mid‑job deferral guard is unchanged (an idle unit's `stop` still SIGTERMs it, just without blocking the loop). Keep the `unit_ctl_bounded` wrapper as a backstop for a genuinely wedged manager, and update the `scale_skip_note`/comment wording that currently describes `--now` semantics. Note in prose: `common.sh`'s `unit_ctl_bounded` (scripts/jobs/common.sh:2257) is the shared bound but needs no change; the fix is confined to how install-units.sh invokes it.
