scripts/jobs/handlers/triager-claude.sh
Failure signature: `garden-triager@kriscendobot-minion.town` exits 1 with only triager.sh's generic `FATAL: triage handler failed for kriscendobot-minion.town; leaving cursor at <none> to retry`. No upstream diagnostic is captured because triager-claude.sh line 50, `out="$(claude -p --dangerously-skip-permissions "$prompt")"`, runs under `set -euo pipefail`: any non-zero exit from `claude -p` (transient API/quota error, rate limit, the unauthenticated `minion-town` MCP server, or a malformed response) kills the handler with zero output, and the parse loop's `post-job.sh` calls (line 58) can likewise die silently.

Change: instrument the `claude -p` invocation and the post loop so a handler failure is diagnosable.
- Capture claude's exit status explicitly instead of letting the bare `$()` under `set -e` abort silently, e.g. redirect stderr to a temp file, run without `set -e` around just that call, and on non-zero exit `log` the exit code plus a `tail` of claude's stderr (and note if `out` was empty) before returning non-zero. This turns the current silent crash into a line the self-heal blob can act on.
- Do the same around `post-job.sh` in the JOB..ENDJOB parse loop: on a non-zero post, log the offending basename and continue/fail deliberately rather than aborting the loop with no context.
- Keep the existing contract intact: still return non-zero to triager.sh so the cursor stays unadvanced and the change re-triages; the only change is that the failure now names its cause.

Rationale: the cursor-retry design means a genuinely transient claude failure is *supposed* to retry, but today every retry is blind and burns a fresh `claude -p` per tick with no way to distinguish transient from structural. Emitting claude's exit code + stderr tail lets the next self-heal tick (or a human) classify the failure instead of re-diagnosing an empty blob. Verify by forcing `GARDEN_TRIAGE_HANDLER`'s claude call to fail (e.g. a stub that exits non-zero to stderr) and confirming the diagnostic line appears in the service log while the cursor stays put.
