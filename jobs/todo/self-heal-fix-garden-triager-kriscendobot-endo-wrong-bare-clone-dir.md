`scripts/jobs/triager.sh` defaults `GARDEN_REPOS:=$GARDEN_ROOT/repos` (line 25) and then dies at line 32 with `FATAL: no bare clone at $GARDEN_ROOT/repos/<slug>.git`. That path is wrong: `$GARDEN_ROOT/repos` does not exist on the host, and the garden's standing bare clones live under `$GARDEN_ROOT/worktrees/<owner>-<name>.git` (canonical per CLAUDE.md, `clone-keeper.sh`, and the shared helpers in `common.sh:442-530`). The needed clone is present at `worktrees/kriscendobot-endo.git`, so the triager is simply looking in the wrong directory and fails every tick. The journal `repos/` watch-set name (armed by `repo-watcher.sh`) is a list of slugs, not a clone dir — the two got conflated.

Fix:
1. In `scripts/jobs/triager.sh:25`, change the default from `: "${GARDEN_REPOS:=$GARDEN_ROOT/repos}"` to `: "${GARDEN_REPOS:=$GARDEN_ROOT/worktrees}"` so `BARE="$GARDEN_REPOS/$slug.git"` resolves to the real clone location.
2. Apply the same default fix in `scripts/jobs/comment-watcher.sh:179` for consistency (it has the identical wrong default; it currently only logs a note rather than dying, so this is latent but should not drift).
3. Recommended (matches the intent documented at `common.sh:444-446`): replace the bare `die "no bare clone at $BARE ..."` at `triager.sh:32` with self-provisioning — when `$BARE` is missing, derive the upstream URL via `derive_clone_url "$BARE"` and clone it with `bounded_clone "$url" "$BARE"` (both already sourced from `common.sh`), logging a `provisioned missing clone` line, and only `die` if provisioning fails. This makes a triager on a host that has never held the clone self-heal instead of failing forever.
