scripts/jobs/auto-gauntlet-handoff.sh
The gauntlet job posted by this handoff (`$base-gauntlet`) carries no `handler-timeout:` header, so the gardener runs it under the default `GARDEN_HANDLER_TIMEOUT` (2400s / 40min). A full gauntlet — clean → panel → fixer loop → CI wait → un-draft — is a strict superset of a shepherd and deterministically overruns 2400s (rc=124), as the new journal entry for `endo-sturdyref-agent-surface-build-gauntlet` shows: the overrun counter is stamped and the reaper early-poisons the job, discarding the build's open draft PR — precisely the silent draft-PR stall this handoff exists to prevent, now re-created by budget starvation. Fix: stamp a gauntlet-sized `handler-timeout:` into the posted job body, following the exact shepherd precedent (`common.sh:28-45`, `comment-watcher.sh:917`, `ci-watcher.sh:347` all use `GARDEN_SHEPHERD_HANDLER_TIMEOUT`). The gauntlet is at least as CI-heavy as a shepherd, so reuse `GARDEN_SHEPHERD_HANDLER_TIMEOUT` (or introduce a `GARDEN_GAUNTLET_HANDLER_TIMEOUT` sourced from common.sh, kept ≤ the claim budget max so the gardener honors it verbatim rather than clamping+escalating). This lets a gauntlet that fits in one claim actually COMPLETE instead of overrunning; a gauntlet that genuinely cannot fit one claim will then trip the gardener's clamp-and-escalate path (gardener.sh:415-417) — a visible "split or run detached" alert — rather than the current silent default-budget overrun. Sibling producer needing the identical header for drift-freedom: `comment-watcher.sh`'s `run the gauntlet` verb path (line ~917) currently stamps `handler-timeout:` only for `verb = shepherd`, not `gauntlet`; extend that condition (or share one helper) so both gauntlet entry points stamp the same value and idempotent re-posts across producers never flap the header.
