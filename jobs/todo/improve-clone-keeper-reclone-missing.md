In `scripts/jobs/clone-keeper.sh`, `keep_clone()` currently logs `WARN: tracked clone <dir> is missing or not a git repo … skipping` and `return 0` when the abs path is absent — so a tracked bare clone that disappears (observed for `worktrees/endojs-endo.git` at 09:30 and again 10:00) is re-warned every tick and never repaired, leaving every downstream worktree/dispatch that depends on that clone broken indefinitely. Add a repair path: when the tracked dir is missing or not a git repo but its remote URL is known (the same `$remote` the keeper already fetches from), re-create the bare clone (`git clone --bare <remote-url> <abs>` then set the tracked branch), logging a `REPAIRED` line; guard it so a genuinely unreachable remote falls back to the existing skip (no re-clone loop) and a present-but-corrupt dir is surfaced as STALE for manual reconciliation rather than clobbered. Add a hermetic case to `scripts/jobs/test/clone-keeper-test.sh` that deletes the tracked clone and asserts the next tick re-creates it.
