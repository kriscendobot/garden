The per-repo watchers cannot find their bare clones because their `GARDEN_REPOS` default points at a directory that does not exist. In `scripts/jobs/triager.sh` the line `: "${GARDEN_REPOS:=$GARDEN_ROOT/repos}"` and in `scripts/jobs/comment-watcher.sh:179` the identical `: "${GARDEN_REPOS:=$GARDEN_ROOT/repos}"` default to `$GARDEN_ROOT/repos`, but the garden's canonical bare-clone location is `$GARDEN_ROOT/worktrees` (see `ensure-project-worktree.sh:63` `bare="$GARDEN_ROOT/worktrees/${owner}-${name}.git"` and `clone-keeper.sh`, which maintains `worktrees/<owner>-<repo>.git` clones such as `worktrees/kriscendobot-vattr97.git`). `$GARDEN_ROOT/repos` does not exist, so EVERY `garden-triager@<slug>` (and `garden-comment-watcher@<slug>`) FATALs with `no bare clone at /home/kris/garden2/repos/<slug>.git (clone the repo first)` on each leader tick — confirmed for kriscendobot-vattr97 AND kriscendobot-endo at 22:51:19, i.e. all watched repos, not just vattr97. Fix: change both `GARDEN_REPOS` defaults from `$GARDEN_ROOT/repos` to `$GARDEN_ROOT/worktrees` (keeping the `${GARDEN_REPOS:=...}` override form). Grep for any other `$GARDEN_ROOT/repos` uses (e.g. `ci-watcher.sh`) and align them the same way, and update the header comment in `triager.sh` that references `$GARDEN_REPOS/<slug>.git`.
