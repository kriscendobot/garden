In `scripts/jobs/common.sh`, teach `sync_clone` (and symmetrically the reset-failure re-fetch it already has) to self-heal a corrupt-but-present journal clone by re-cloning once, mirroring the existing poisoned-partial-clone guard in `ensure_clone` (common.sh:1541-1557) and the offline classification in sync_clone (common.sh:2506-2510).

Failure signature (observed on `cleric/7`, clone `/home/kris/garden/.garden-state/clerics/7/journal`): `journal_fetch` fails with a NON-offline rc whose `GARDEN_FETCH_STDERR` contains `fatal: bad object refs/remotes/origin/journal2`, `did not send all necessary objects`, `failed to run repack`, plus a stale `.git/gc.log` warning. Bounded retries cannot fix persistent object-store corruption, so sync_clone hits `die "fetch failed in $dir after bounded retries"` (common.sh:2510) → `gardener.sh:291` and the worker FATALs on EVERY tick forever.

Change:
1. Add a `GARDEN_CORRUPT_CLONE_SIGNATURES` regex (single source of truth, alongside `GARDEN_OFFLINE_SIGNATURES`) covering: `bad object`, `did not send all necessary objects`, `failed to run repack`, `gc\.log`, `loose object .* is corrupt`, `object file .* is empty`, `unable to read (tree|sha1)`, `fsck`, `packfile .* cannot be accessed`. Add a classifier `_fetch_stderr_is_corrupt` matching it case-insensitively.
2. In `sync_clone`, before the `die` at common.sh:2510: if the failure is not offline/timeout but `_fetch_stderr_is_corrupt "$GARDEN_FETCH_STDERR"` matches, log a WARN ("corrupt journal clone $dir; self-healing by re-cloning"), then under the already-held `clone_lock` `rm -rf "$dir"`, call `ensure_clone "$dir"` (which now hits its fresh-clone path since `.git` is gone) and retry `journal_fetch` ONCE. Re-clone at most once per tick to avoid a reclone loop; if the retry still fails, fall through to the existing `die`.
3. Guard against an infinite reclone-per-tick with a sentinel (e.g. a `reclone_attempted` local), so a genuinely unrecoverable remote still dies loud rather than spinning.
4. Add a unit test under `scripts/jobs/test/` injecting a `GARDEN_FETCH_CMD` that emits the `bad object` / `did not send all necessary objects` stderr, asserting sync_clone re-clones and recovers instead of dying (mirroring the poisoned-partial-clone and offline-classification tests).

Note the corrupt clone is per-worker state under `.garden-state/clerics/<n>/journal`; the guard must key off the passed `$dir`, not the shared bare clone.
