`garden-repo-watcher` (and any service using a `.garden-state/<svc>/journal` mirror clone) dies permanently when that clone's local `refs/heads/journal2` is corrupt. Failure signature in the fetch stderr: `fatal: bad object refs/heads/journal2` + `did not send all necessary objects` + `error: bad ref for .git/logs/refs/heads/journal2`. Root cause on the affected clone (`.garden-state/repo-watcher/journal`): an auto-`git gc` crashed with a glibc malloc assertion (stale `.git/gc.log.lock` from 2026-07-10 records `Fatal glibc error: malloc.c:2599 (sysmalloc): assertion failed`), truncating the loose `refs/heads/journal2` to 0 bytes so it reads as an all-zeros broken ref and shadows the valid `packed-refs` entry. The remote-tracking ref is fine, so this is pure local corruption that `journal_fetch`/`sync_clone` never classify as offline and never repair, and `ensure_clone` skips because `.git` still exists — so systemd restarts into the identical failure indefinitely.

Fix (in `scripts/jobs/common.sh`), mirroring the poisoned-partial-clone self-heal at `ensure_clone` (~lines 1554-1566):
1. Add a corruption-repair step for these state-dir journal mirrors. When `journal_fetch` fails (in `sync_clone`, before the `die "fetch failed in $dir after bounded retries"` at ~line 2510) AND the captured `$GARDEN_FETCH_STDERR` matches a local-corruption signature (`bad object refs/heads/`, `bad ref for `, `did not send all necessary objects`, or a broken/zero-length loose ref detectable via `git -C "$dir" show-ref --verify refs/heads/$JOURNAL_BRANCH` failing while `packed-refs` / `origin/$JOURNAL_BRANCH` resolves), self-heal by `rm -rf "$dir"` and calling `ensure_clone "$dir"` to re-clone fresh from origin (these mirrors hold no unpushed state), then retry the fetch/reset once. Log a `WARN: … self-healing corrupt journal clone by re-cloning` line like the existing poisoned-clone path.
2. Keep the repair scoped to the offline-vs-corruption classifier so a genuine transient outage still takes the clean EX_TEMPFAIL skip and only real local corruption triggers a re-clone.
3. Also clear a stale `.git/gc.log.lock` as part of the repair (or rely on the full `rm -rf` re-clone, which covers it).
4. Add a test under `scripts/jobs/test/` that seeds a clone with a zeroed `refs/heads/journal2` loose ref shadowing a valid `packed-refs` entry (plus a stale `gc.log.lock`) and asserts `sync_clone` self-heals to a working clone instead of dying.

Immediate one-shot unblock for the currently-wedged instance (safe to run now): `rm -rf /home/kris/garden/.garden-state/repo-watcher/journal` — the next tick's `ensure_clone` re-clones it. The code change makes this automatic and fleet-wide.
