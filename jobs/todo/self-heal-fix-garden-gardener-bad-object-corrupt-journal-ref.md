`scripts/jobs/common.sh`: harden `journal_fetch`/`sync_clone` against a **persistent corrupt journal clone** that currently crash-loops a gardener. Failure signature: after `GARDEN_FETCH_RETRIES` the fetch keeps failing with `fatal: bad object refs/remotes/origin/<branch>` (and often `warning: … remove .git/gc.log` / `failed to run repack`); `git fsck` shows `refs/remotes/origin/<branch>: invalid sha1 pointer 000…0` from a **zero-byte loose ref** shadowing the valid packed-ref. Because the stderr matches no `GARDEN_OFFLINE_SIGNATURES`, `sync_clone` (common.sh:2510) `die()`s and systemd restarts into an infinite loop.

Fix: when a fetch fails with a **non-offline, corruption** signature (`bad object refs/`, `invalid sha1 pointer`, `did not send all necessary objects`, `failed to run repack`, or a stale `.git/gc.log` present), self-heal the clone before dying — in a new helper (e.g. `repair_corrupt_clone <dir>`) called from `journal_fetch`'s exhausted-retry branch (common.sh:1686) or right before `sync_clone`'s `die`:
  1. Remove the stale `<dir>/.git/gc.log`.
  2. Prune any zero-byte loose ref under `<dir>/.git/refs/remotes/origin/` (or `git for-each-ref`/`git update-ref -d` where the ref is unreadable; a truncated file needs a plain `rm` since update-ref can't parse it), so the valid packed-ref is unshadowed.
  3. `git -C <dir> fetch --prune` once more; if it still fails, fall back to a clean re-clone of the journal via the existing `ensure_clone` path.
Then log the repair (one line, distinct from the offline-skip line) and either succeed or take the EX_TEMPFAIL/`die` path as appropriate. Guard the repair so it only fires on the corruption signatures, never on a genuine offline outage. Add a test alongside the existing fetch-classification tests injecting the `bad object refs/…` + gc.log shape and asserting the clone is repaired rather than the worker dying. Also repair the currently-corrupt live clone at `.garden-state/gardeners/11/journal` (rm the 0-byte `.git/refs/remotes/origin/journal2` and `.git/gc.log`) so gardener 11 recovers immediately.
