`ensure_clone()` (common.sh ~L992) FATAL-loops with no self-heal when its destination directory exists but is a broken/partial clone. It clones only `if [ ! -d "$dir/.git" ]`, then `git clone -q --single-branch --branch "$JOURNAL_BRANCH" "$remote" "$dir" || die "clone of $remote ($JOURNAL_BRANCH) into $dir failed"`. But `git clone` refuses a destination that already exists and is non-empty, so once a prior clone is interrupted (SIGKILL at TimeoutStop, a `sync_clone` reset aborted mid-flight, disk hiccup) and leaves `$dir` populated without `.git`, EVERY subsequent tick hits the `die` — forever, with no recovery.

Evidence: the captured `journalctl garden-*` tail shows `[unblock] FATAL: clone of git@github.com:kriskowal/garden.git (journal2) into /home/kris/.garden-state/unblock/journal failed` **145 times**, once per ~5-minute timer firing from 05:13Z straight through 17:14Z (≈12 hours), plus one identical `[orchestrate] FATAL: ... into /home/kris/.garden-state/orch/journal`. During that whole window the remote was reachable (`git ls-remote` succeeds now) and the rest of the fleet was running jobs — so this is a stuck-destination-state defect specific to the self-provisioning clone path, not the transient quota/network outages that dominate the older journal entries. The unblock watcher (deterministic board moves) and orchestrate watcher stayed dead the entire time.

Change: inside `ensure_clone`, under the `clone_lock "$dir"` it already holds, when `$dir` exists but `$dir/.git` is absent, treat it as a poisoned partial clone and clear it (`rm -rf "$dir"`) before cloning — better still, clone into a sibling temp path and atomically `mv`/rename into place so an interrupted clone can never again leave a non-empty destination that wedges the retry. Log a single WARN when self-healing a partial clone so the recovery is visible. This is shared code: `unblock.sh`, `orchestrate.sh`, and every other watcher that self-provisions its journal via `ensure_clone` all inherit the fix.

Related but out of scope for this job (named per the single-script rule): `unblock.sh` and `orchestrate.sh` are the two observed callers; no change is needed in them once `ensure_clone` self-heals.
