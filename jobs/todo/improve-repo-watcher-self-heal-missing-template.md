In `scripts/jobs/repo-watcher.sh`, `reconcile_set()` arms `<prefix>@<slug>.timer` per journal file and, on failure, only logs `WARN: could not arm ...` — which repeats every tick forever when the *template* unit itself (`<prefix>@.service`/`.timer`) is absent from the user manager. This is currently the live state for `garden-ci-watcher@*` on endolinbot: the templates exist in `scripts/systemd/` (added in `1a9448720`) but were never rendered into `$DEST`, so `enable --now garden-ci-watcher@<slug>.timer` fails ("Unit file ... does not exist") on every reconcile and the auto-shepherd CI watch never actually runs. The existing pre-arm `daemon-reload` comment (lines 77-84) already acknowledges this class of arming race but doesn't cover a template that was never installed. Harden it to self-heal drift deterministically: before (or on first arm-failure within) `reconcile_set`, check whether the template unit file for `$prefix` is present (`unit_ctl list-unit-files "$prefix@.service"` / a `$DEST/$prefix@.service` existence test); if absent, invoke `scripts/jobs/install-units.sh install` once per tick to render+daemon-reload the missing templates, then retry the arm. Guard the install call so it runs at most once per tick (only when a needed template is genuinely missing) to avoid a heavy install on the common no-drift path. This moves the "a human/agent must re-run install-units after new template units ship" responsibility into the script and stops the every-minute WARN spam that drowns real warnings in the `journalctl -p warning` tail.
