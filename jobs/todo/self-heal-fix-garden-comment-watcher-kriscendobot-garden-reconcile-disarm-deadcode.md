The comment/CI/triager watchers for the dead fork `kriscendobot/garden` (repo 404 on GitHub) keep flapping on leader host `endolin-garden-ece02cb4` even though the journal was already tombstoned (`watch-optout/kriscendobot-garden`) and its `comment-repos/`/`repos/` arming records deleted. Root cause: `scripts/jobs/repo-watcher.sh` `reconcile_set()` (line ~168) builds its `have[]` set of already-armed instances from `systemctl --user list-unit-files "$prefix@*.timer"`. Empirically on real systemd that lists ONLY the bare template `garden-comment-watcher@.timer` (verified: it returns just `garden-comment-watcher@.timer indirect enabled`), never the instantiated `@<slug>.timer` symlinks — whereas `list-units --all "$prefix@*.timer"` DOES enumerate every armed instance (verified: 18 instances incl. `@kriscendobot-garden`). So `have[]` is always empty, and the disarm loop at lines ~193-198 (`for slug in "${!have[@]}"; … disable --now`) is dead code: an arming file removed from `comment-repos/`/`repos/` never tears down its still-enabled per-repo units, which then flap against whatever their target now is (here, a 404 repo) forever.

Fix, three parts:
1. `scripts/jobs/repo-watcher.sh`: change the `have[]` discovery in `reconcile_set` from `list-unit-files "$prefix@*.timer"` to `list-units --all "$prefix@*.timer"` (keep the same `"$prefix"@*.timer` case-match and the `[ -n "$inst" ]` bare-template skip; `list-units` output columns still lead with the unit name so the `read -r unit _` parse is unchanged). This makes the disarm loop live so a de-armed slug is actually `disable --now`'d. Applies to all three reconciled sets (garden-triager, garden-comment-watcher, garden-ci-watcher at lines ~218-220).
2. `scripts/jobs/test/mock-systemctl.sh` (line ~56): stop answering `list-units` and `list-unit-files` identically — that parity hole is why the test passed while production couldn't disarm. Make `list-unit-files "<prefix>@*.timer"` return only the bare template `"<prefix>@.timer"` (model systemd's "unit files on disk" semantics), and keep `list-units --all` returning the instantiated armed set from `$STATE`. 
3. Add a regression case (extend an existing watcher test that drives repo-watcher, or add `scripts/jobs/test/repo-watcher-test.sh`) asserting: arm a slug, remove its arming file, re-run reconcile, and assert the instance timer is `disable`d — which fails under the corrected mock until part 1 lands.

Also perform the immediate host-local remediation the reconcile can't yet do: `systemctl --user disable --now garden-comment-watcher@kriscendobot-garden.timer garden-ci-watcher@kriscendobot-garden.timer garden-triager@kriscendobot-garden.timer` on whatever host runs this job (the slug is already tombstoned + absent from both journal sets, so a fixed reconcile will not re-arm it). Note the deploy of parts 1-2 rides `main2` via the normal deliberate-deploy path, which is what finally lets every host auto-disarm de-armed slugs.
