`sync_clone` / `ensure_clone` do not self-heal a journal clone whose `.git` exists but whose refs/reflogs are corrupt. Incident (garden-repo-watcher, exit 1, recurring every tick): the clone at `$GARDEN_STATE/repo-watcher/journal` had `refs/heads/journal2` zeroed to an all-zero SHA (`fsck`: `invalid sha1 pointer 0000…0000`, `invalid HEAD`, `bad ref for .git/logs/refs/heads/journal2`, `bad ref for .git/logs/HEAD`) — a crash/SIGKILL mid ref-update. Every `git fetch` then aborts locally with `fatal: bad object refs/heads/journal2` + `did not send all necessary objects` before contacting the remote. `journal_fetch` exhausts its bounded retries, the stderr matches no `GARDEN_OFFLINE_SIGNATURES`, so `sync_clone` reaches `die "fetch failed in $dir after bounded retries"` and the unit fails on **every** tick. `ensure_clone`'s poisoned-partial-clone recovery is gated on `[ ! -d "$dir/.git" ]` (line ~1541), which a corrupt-but-present `.git` slips past.

Fix (mirror the existing poisoned-partial-clone self-heal, but for the corrupt-refs class): add a local-corruption stderr classifier alongside `_fetch_stderr_is_offline` — e.g. `_fetch_stderr_is_local_corruption` matching (case-insensitively) `bad object`, `bad ref`, `did not send all necessary objects`, `invalid sha1 pointer`, `unable to read`, `object file .* is empty`, `loose object .* is corrupt`. In `sync_clone`, in the `rc != 0` branch, BEFORE the final `die`: if the fetch failed AND stderr matches the corruption signature (and it is not an offline signature), `log "WARN: <dir> journal clone corrupt (<signature>); self-healing by re-cloning"`, `clone_unlock "$dir"`, `rm -rf "$dir"`, `ensure_clone "$dir"` (which atomically re-clones fresh), then `journal_fetch "$dir"` once more; only `die` if that re-clone+fetch still fails. Keep it reactive (only on the failure path, no per-tick cost) and bounded (re-clone at most once per `sync_clone` call so a genuinely un-cloneable remote still dies loud rather than looping). Add a test alongside the existing sync_clone offline-classification tests injecting a `GARDEN_FETCH_CMD` that emits the `bad object … did not send all necessary objects` stderr and asserting sync_clone re-clones instead of dying. This closes the same reliability gap for every consumer of `sync_clone` (all watchers, the foreman, unblock/orchestrate), not just the repo-watcher.
