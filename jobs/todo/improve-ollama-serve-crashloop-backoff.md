scripts/jobs/ollama-serve.sh
`garden-ollama.service` crash-loops every ~5s indefinitely on a host where the endpoint cannot come up (observed 2026-07-22 on endolin-garden2-5bcdff64: hundreds of consecutive `Failed with result 'exit-code'` in the warning tail, flooding the journal). The script ends in `exec ollama serve`, so a fast-failing serve returns to systemd immediately and `Restart=always`+`RestartSec=5`+`StartLimitIntervalSec=0` hot-loops forever. Harden the script to distinguish a permanent precondition from a transient crash and to throttle the retry cadence itself rather than relying on systemd's fixed 5s:

1. Preflight the two permanent-failure cases before serving. (a) If the endpoint already answers (`curl -fsS --max-time 5 "$GARDEN_LOCAL_OLLAMA_URL/models"` succeeds — a stray/duplicate `ollama` already holds the port), do NOT `exec ollama serve` (it would fail "address already in use" and hot-loop); log once and sleep-block (or exit after a long backoff) so systemd isn't restarting into a doomed bind every 5s. (b) The existing `die` on missing `ollama` binary should back off, not exit instantly.

2. Stop `exec`-ing so the script can observe serve's exit: run `ollama serve` as a child, and on any non-signalled exit `sleep` a backoff (e.g. 30–60s, ideally capped/escalating) before the script returns, converting systemd's 5s hot-loop into a low-noise slow retry. Preserve the clean-exit-on-SIGTERM/SIGINT contract (unit's `SuccessExitStatus=143 130`) so a systemd stop/deploy still counts as clean and does not incur the backoff.

Net effect: a host that genuinely cannot serve (missing binary, occupied port, no GPU access) retries quietly on a long interval and emits one clear diagnostic, instead of writing a warning every 5 seconds forever. Keep the existing `OLLAMA_IGPU_ENABLE=1` / `OLLAMA_HOST` derivation intact. The companion unit keys (`RestartSec`, `StartLimitIntervalSec`) in `scripts/systemd/garden-ollama.service` may be tuned to match, but the throttle must live primarily in the script so it survives a serve that exits 0-but-immediately.
