## What the problem actually was

Two different units can own `:11434`, and which one does is per-host — the messaging assumed one:

| Unit | Scope | State on this host |
| --- | --- | --- |
| `garden-ollama.service` | `systemctl --user` (bot user) | **installed but disabled** — hermit-count-gated by `install-units.sh reconcile_ollama_unit`, and `hosts/endolin-garden2-5bcdff64` has `hermits: 0` |
| `ollama.service` | system unit, runs as the `ollama` user | **enabled + active since 06:19, holding the port**, serving an empty model list |

The system unit is enabled because this container's image was built at 05:22–05:26 from a tree predating `d4a40ed9ba` (2026-07-28 01:30, "make garden Ollama the sole endpoint owner"), which removed the Dockerfile's `systemctl enable ollama.service` + `igpu.conf` drop-in. That's a **build-time** change, so every container from an earlier image still diverges from the invariant the docs asserted.

So the old guidance sent an operator to a unit that is disabled by design *and* that they could not start into service anyway — starting it fails on address-in-use, the exact case `ollama-serve.sh` already refuses to stand down for.
