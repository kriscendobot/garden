## Touch points (headlines; full report with section citations in the result entry)
**Endo:**
- **Git remotes:** Pando serves fetches as links to stored packs that clients download from a cache (`packfile-uri`). That fits `daemon-git-remotes`, which already sends pack bytes outside CapTP; a daemon could hand out cacheable links to specific packs.
- **Stacked PRs:** a server that advertises only trunk makes the client resend the whole stack on every push, which matters for the force-with-lease push tier (#705).
- **Endor bindings:** Pando never unpacks a push into a local repository; it only picks stored packs. That is an option for the object-database seam in `endor-git-bindings` and the minion.town server half.
- **Storage and CAS:** in Pando the only contended key is a ref pointer guarded by compare-and-swap, and there is no snapshot across all refs. This matches the 2026-11-03 opaque-identity direction for CAS, and argues against requiring an atomic snapshot across directories (#1358, #1586). Pando also never garbage-collects packs; it compacts them in levels instead, a counterpoint to the mark/sweep GC in `daemon-cas-management`.
- **npm-CAS registry:** the Express regional cache and the proxy-first migration that merges duplicate requests apply to the registry proxy.
- **CI:** the post describes the same load the Endo fleet creates (each push sets several jobs fetching one commit). Its testing approach (a conformance suite agents test against, deterministic simulation, agent-written TLA+ and Lean) carries over.

**Git and the garden:**
- **journal2:** the write-ahead-log design the post rejects (every writer compare-and-swaps one shared manifest) is how journal2 works. Pando's fix, making each ref its own unit of serialization, supports the journal3 split and suggests splitting further by area.
- **Reader cost:** the post's pack reuse and request deduplication line up with the garden's shallow staging clones, borrowed objects and the fetch freshness window.
- **Repo maintenance:** Pando compacts packs in the background in place of repack/gc. Stock Git's geometric or incremental `git maintenance` could do the same for the shared root repo and avoid the `gc.log` failure mode. This is worth a follow-up design; I did not post one.
- **Push and advertisement:** "explicit haves" with `--force-with-lease`, `packfile-uri`, and the cost of advertising many refs (frozen-base refs pile up on the forks).
