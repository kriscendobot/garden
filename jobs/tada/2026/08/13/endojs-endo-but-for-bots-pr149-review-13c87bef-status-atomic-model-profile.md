## Disposition: **(4) explicitly omit — in this exact form**

The feature as scoped (secret-bearing persistence + ambient env-stamping + primordial precedence) is **not honored** on `origin/llm` and should **not** be integrated as-is. The reusable *machinery* is a separable, lower-value residue (see carve-out).

### Evidence

1. **Entirely absent from `origin/llm`, and genie-experiment-specific.** There is no `packages/genie/src/primordial/` directory on `origin/llm` at all — no `persistence.js`, no `/model` handler, no primordial mode. `origin/llm:packages/genie/main.js` has zero references to `GENIE_MODEL`, `primordial`, `loadConfig`, or `resolveBootMode`. The whole subsystem is a PR-branch construct (feature commit [`ad2cfd7eb`](https://github.com/endojs/endo-but-for-bots/commit/ad2cfd7ebc9b8146d0f2bc293287a27a0931970a)).

2. **The credential-storage core directly conflicts with — and would regress — the current agentry credential seam.** The feature persists plaintext credentials to `<workspace>/.genie/config.json` ([`persistence.js` saveConfig, `credentials: {...credsRaw}` written to disk](https://github.com/endojs/endo-but-for-bots/blob/e0c8accb3235a340ce2b4e4307138429a7d1e5f3/packages/genie/src/primordial/persistence.js)) and then copies them into ambient env at boot via `stampPersistedEnv` ([`main.js` L2082–2092: `process.env[key] = value`](https://github.com/endojs/endo-but-for-bots/blob/e0c8accb3235a340ce2b4e4307138429a7d1e5f3/packages/genie/main.js#L2082-L2092)). Current [`origin/llm:packages/agentry/src/harness/credentials.js`](https://github.com/endojs/endo-but-for-bots/blob/a54c3adbebf18fd837770d467433e480de498e8d/packages/agentry/src/harness/credentials.js) moves in the **opposite** direction: it made the process-env record *no longer the default* (callers must pass `getAmbientEnv()` explicitly), funnels every secret read through `credentials.get()`, and carries a standing `TODO(secure)` to swap the env-backed provider for a capability-scoped secret store. Porting the feature's env-stamping would re-hide the ambient-env dependency the seam just made explicit.

3. **The plaintext hazard is acknowledged in the feature's own code.** The forced README pointer written into every config file reads: `"Generated by /model commit. Plaintext — see CLAUDE.md before checking in."` ([`persistence.js` `README_TEXT`](https://github.com/endojs/endo-but-for-bots/blob/e0c8accb3235a340ce2b4e4307138429a7d1e5f3/packages/genie/src/primordial/persistence.js)).

4. **The precedence half carries a known defect** (from `discover-genie-core`, verified in source): a worker launched with `GENIE_MODEL` keeps that env value in its retained formula, and boot precedence continues to prefer it over a newly persisted `/model commit`, so model replacement never takes effect ([`main.js` `resolveBootMode` L2048–2058](https://github.com/endojs/endo-but-for-bots/blob/e0c8accb3235a340ce2b4e4307138429a7d1e5f3/packages/genie/main.js#L2048)). Another reason not to port the precedence rule verbatim.

### Carve-out (the one reusable residue — a note, not an integration ask)

The atomic, schema-versioned file machinery (`loadConfig`/`saveConfig`/`clearConfig`/`validateConfig`: temp-file → `fsync` → `rename` → `chmod 0600`, never-throw versioned load) is clean and well-tested. **But it is not novel to the repo:** `origin/llm` already ships an atomic write-then-rename helper, [`atomicWriteJSON` in `packages/genie/src/interval/persistence.js`](https://github.com/endojs/endo-but-for-bots/blob/a54c3adbebf18fd837770d467433e480de498e8d/packages/genie/src/interval/persistence.js) (though without `fsync`, `chmod 0600`, or schema-versioning). If a **non-secret** model-profile store is ever wanted, the right move is to harden that existing helper (add fsync/versioning) in `agentry`, *not* to import PR #149's secret-bearing variant. The `0600` atomic-write discipline is only worth carrying because the file holds secrets — remove the secrets and the ordinary atomic helper suffices.

This is a secondary (disposition-5-flavored) pointer, subordinate to the primary omit.

## Bottom line

**Omit in this exact form.** The feature is absent from `origin/llm`, genie-experiment-specific, and its secret-persistence + ambient-env-stamping core actively contradicts the direction of `origin/llm`'s agentry credential seam. The only forward-looking residue is a note (not a port): if a non-secret model-profile store is ever desired, harden `origin/llm`'s existing `atomicWriteJSON` in agentry rather than importing this credential-bearing implementation; migrate the `TADA/92–97` design rationale into the journal as the durable record.
