```markdown
## Harden the OCapN gateway: bind `followRetentionSet` to the authenticated peer

Development branch only — `master` has no retention following and is unaffected.

### The class of defect

The OCapN daemon gateway (`packages/daemon/src/daemon.js`) exposes two methods to
a remote client: `provide` and `followRetentionSet`. `provide` is a *bearer* read
— it answers only for a caller that already holds the secret formula id it names,
and it enumerates nothing. `followRetentionSet` is the one method that *reveals*
formula numbers.

The gateway returned by the `hello` greeter was shared and unbound:
`followRetentionSet(node)` ran `listFormulaNumbersByNode` on whatever node number
the caller supplied, with no binding to the node the connection actually
authenticated. Because a node's own formula-number index is the secret that keeps
its `provide` safe, an enumerating method that is not confined to the caller's own
node undermines that secrecy — the local node's index in particular must never be
externally enumerable. This is an authorization defect in the gateway surface, not
a memory-safety or protocol bug.

### The fix

Two invariants, enforced structurally:

1. **Peer-bound gateway.** `hello` now hands back a gateway bound to the node the
   connection authenticated (`makeGatewayForPeer`). Its `followRetentionSet`
   answers only for that bound node — never another peer's node, and never the
   local node.
2. **Local index never enumerable.** The shared `localGateway` (presented on
   outbound and loopback connections, which do not authenticate a single peer
   in-band) refuses outright to enumerate the local node's formula index. No
   legitimate caller ever follows the local node's own retention set — a node
   never peers with itself — so this closes the non-`hello` path without
   affecting interop.

`provide` is extracted (`gatewayProvide`) and shared unchanged between both
gateways; it already answers only for a held secret id and enumerates nothing.
`followRetentionSet` is the only enumerating method on the gateway, so it is the
only one that could destroy that secrecy. This branch has no `provideBlob` /
`provideTree`, so `followRetentionSet` is the entire enumerating surface here.

### Tests

Added to `packages/daemon/test/endo.test.js`, driving the daemon's own
greeter/gateway over the local socket — the same objects an inbound OCapN peer
reaches via `hello`:

- **`gateway from hello binds followRetentionSet to the authenticated peer`** — an
  authenticated peer can follow only its own node's retention set; the local node
  and any third node are refused.
- **`shared gateway refuses to enumerate the local node formula index`** — the
  shared gateway refuses the local node while still answering for a remote node.
- A positive interop control — a peer-bound gateway still `provide`s a local value
  the caller holds the id for.

The cross-daemon invite/retention suite continues to pass, so peer-to-peer
retention following is unaffected.

### Known follow-up (out of scope here)

On the *outbound* path, the gateway a daemon presents to a peer it dials is not
yet bound to that specific dialed peer, so a dialed peer could still be asked to
follow a *third* node's retention set (the local node remains refused on every
path). Binding the outbound direction requires threading the peer identity
through the host `gateway()` powers facet across all transports; it is tracked
separately and is **not** addressed by this change.
```
