scripts/jobs/dependabot-watcher.sh
The watcher posts one full botanist job per open `dependabot[bot]` PR with no cross-PR reconciliation, so every stale duplicate buys a complete Opus review (lockfile transitive set, scripts-disabled install, upstream source read, advisory cross-check, local suite runs) whose only output is "REJECT, superseded, closed". This tick that happened four times on one repo: 561 and 560 closed as superseded literal duplicates, 562 closed in favor of 869 (same dependency, same three `package.json` files, same `llm` base, newer target, current base, fresher green CI), and 268 closed because base `llm` already pins a newer `actions/setup-node` at exactly the six call sites the PR touches. The supersession judgement is deterministic and a botanist already wrote the check out: for two PRs moving the same dependency to different versions, `gh api "repos/<upstream>/compare/v<old>...v<new>" -q '{status:.status,ahead:.ahead_by,behind:.behind_by}'` — `behind_by: 0` proves the newer tag strictly contains the older, and a non-zero `behind_by` means a divergent release line where the supersession claim does not hold without a human-grade read. Add a preflight pass over the enumerated dependabot PRs before the posting loop: group them by the package they move, and where a group has more than one member, resolve containment via the compare API and post the full botanist job only for the dominating PR, while the dominated ones get a cheap close-as-superseded job body that carries the already-computed evidence (the peer PR URL and the compare result) instead of commissioning a fresh end-to-end review. Where containment cannot be established, fall open to the current behavior — post the full review for both — so a divergent release line is never auto-closed. This needs the dependency identity, which the PR source does not currently emit: its columns are `number author head_repo updated_at`, so extend the source (`scripts/jobs/handlers/ci-pr-source-gh.sh`) to carry `title` and parse the `bump <pkg> from <a> to <b>` form, treating an unparseable title as ungrouped. A second, cheaper leg worth the same preflight is the 268 case — the base branch already carrying a newer pin than the PR proposes — but that one is repo-shaped and should stay in the job body as a first-step instruction unless it can be read deterministically from the diff.
