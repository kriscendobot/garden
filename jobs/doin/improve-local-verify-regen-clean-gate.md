Add a codegen-then-clean gate so stale checked-in generated artifacts are caught locally instead of on CI. Two changes: (1) add a `codegen` step to `STEPS` whose `candidates()` match a project's generator scripts (e.g. `gen:code-mode-types codegen gen generate build:types`), so the generators run as part of the gate rather than being left to an agent's memory; (2) after all steps complete, check `git -C "$wt" status --porcelain` — if the worktree became dirty (a generator regenerated a checked-in artifact), fail the gate with a clear message ("STEP codegen left tree dirty: generated artifacts are stale — commit the regen") plus a `git diff --stat` (SHA-captured via `capture_blob` like other failures, to protect the supervising agent's context), and increment `failures`. This directly hardens against the recurring endo-but-for-bots failure: rebasing a PR that touches the platform-fs guards or exo-git types staled `packages/agentry/src/execute/{git,fs}-types.js` (regenerated by `yarn workspace @endo/agentry gen:code-mode-types`, guarded by agentry's code-mode-types divergence-gate test), silently failing all CI test jobs after approval (endojs/endo-but-for-bots#714, cost a red cycle until commit 85f262135d). Because the gate is silent-on-success and content-addresses failures, this stays within local-verify's existing discipline. Keep it generic — any project with a mutating generator benefits; endo is just the first witness. A lighter alternative (project-notes seam) would be a one-line post-rebase note in the weaver/`rebase-hygiene-audit` skill, but that still relies on an agent following it; the eval-gate change removes the human step entirely.
